# Changelog

本包（`qishui-tui`）的变更记录，最新在上。

## Unreleased

### Fixed

- **设置页的缓存统计数字从来没画出来过**：`SectionView` 用「可选中项」的下标去查 `note`，而设置页的统计行全是 `disabled` 的纯信息行——标签画了、右侧数字永远是空。现在 `flattenSections()` 把 `note` 直接挂在行上，不可选中行照常显示；补 `test/entries.test.ts` 钉住这条（disabled 行保留 note、且不进可选中列表）

### Changed

- **设置页的缓存统计与校验重做：按真实字节拆开、试听片段不再算「坏文件」**
  - 统计：`媒体缓存` 一行给「N 首 · 真实占用 X · 试听 M 首」，下面拆「占用明细（音频/封面/歌词/记录）」「残留（`.part`/孤儿目录）」「待重下（大小对不上，下次播放重下）」「容量」；数字全部来自 core 的 `MediaStats`（真实字节），四项之和加残留 = 已用，不再拿 meta 自报的 `audio.bytes` 相加
  - 校验：新增「深度校验（sha1）」（算内容指纹，慢一些）与「修复校验问题」（确认框写明只改记录、能播的音频不动、缺音频的目录才删）；结果段给概览 + 说明（试听多少首、旧版记录多少首、是否算了 sha1、用时）+ 逐条问题（级别/曲名/说明，最多 30 条）
  - 文案收进 `src/ui/cacheView.ts`（纯函数，`test/cacheView.test.ts` 覆盖容量档位名、残留描述、概览与单条问题），页面不再散着拼字符串

### Fixed

- **出声报错：贴错曲目、贴不出来、以及「按两下喜欢只喜欢了一次」**
  - **症状**：① mpv 报「打不开」以后那句话一直挂在播放条上，换到下一首还在（看着像新一首也坏了），而它在有曲目时**根本不画**——只在「没有曲目」那一支里输出，正常在播时整条报错被吞掉；② 快速连点两首时，上一首那个进程起不来的报错会算在新的一首头上（新那一首明明好好的）；③ 同一首连按两次 `[喜欢]`，两下都从「还没写完的老状态」出发算，结果是喜欢了两次，取消不掉
  - **做法**：① `context.tsx` 把报错存成 `AudioNote { trackId, text }`（`onError` 记下**当时那一首**的 id），`snapshotOf` 只在 `note.trackId === 当前曲目 id` 时才把话带进快照，`source` 事件（新一首、或同一首重播）先清 —— 一句话只属于它发生的那一首；`PlayerBar` 把它画在有曲目那一支（新增纯函数 `noteWidthOf`：最多 24 列，长句按余量截断，连 8 列都凑不出就宁可不说，因为播放条在定高布局里折一行会把 HintBar 顶出屏外），无曲目那一支也补成可收缩盒；② `mpv.ts` 的 `child.on('error')` 先认 `generation`——已被下一次 `start` 顶掉的那个进程，它的故障不是「这一首」的故障（`available = false` 照记，那是这台机器的全局事实）；③ `rowActions.ts` 按曲目 id 串一条 `likeQueue`，第二下等第一下写完，且链上只挂「这一格跑完」（前一次失败不许把后一次一起带走）；判「现在算不算已喜欢」把 `data.state.isCollected` 排在 `liked` 前面——`liked` 是实体到手那一刻的老水印，连按时只有前者跟得上真相
  - **边界**：报错那句的截断走 `displayWidth()`，宽度算的是这一格本身、末尾多留 1 列给 `gap={1}`，不然「刚好挤满」那一帧会折行；`likeQueue` 跑完自己摘掉条目，不留每首一条的常驻 map
  - 离线单测：`test/playerBar.test.ts`（新增文件）断 `noteWidthOf` 的四种余量与被顶掉的进程只报一次；`test/rowActions.test.ts` 断连按两次是 `like` → `unlike`

- **鼠标：弹层开着时不再穿透到底层那一行**：加了一层 `MouseBlock` 作用域（`App.tsx` 只把 `BaseLayer` 包进去）
  - **症状**：弹层（操作菜单/歌词/评论）开着时底层页面**不卸载**（要保住已取的数据与游标），但它的布局矩形还在——`hitTest` 照样命中，于是点弹层里的按钮会**同时**驱动底下那一行，滚轮也是两边一起滚
  - **做法**：点击与滚轮的 handler 在「本层被挡」时干脆不注册；弹层自己不在这棵子树里，照常接鼠标
  - **边界**：不能在页面里判断「有弹层就关掉鼠标」——`ActionMenu` 自己就复用 `SectionView`，那样会把弹层自己的鼠标一起杀掉
- **封面两处白闪/互相擦**：① 本地封面的 kitty 图像 id 全撞车——走 `loadBytes` 时 `url` 是空串，`coverId('')` 让详情页与听歌页塌成**同一张图**，互相盖、卸载把另一张也擦掉（id 现在跟缓存键同一身份 `opts.key ?? url`）；② 拖窗口时每帧都在变 cols/rows，从前一律先 `setArt(undefined)` 再重解码——一路闪空白。现在「同一张图换个尺寸」留着上一帧的老封面，新解码回来再换；**换曲目/换页**（身份变了）才抹
- **窄终端不再被撑破**（三处宽度/高度口径）：
  - 弹层 `Modal` 的 `Math.max(40, …)` 下限在 40 列以内的终端里会把框顶出屏幕——下限改成跟着 `stdout.columns` 收（并留 12 列保底，再窄就装不下边框 + padding）
  - 播放条从前按「`columns − 侧栏宽`」算，还带一个 40 的保底：它是侧栏的**兄弟盒**、本来就占满整屏，白白少用十几列；更糟的是窄终端硬撑到 40 列会超实际列宽整条折行，定高布局下 HintBar 被挤出屏外（看着像「提示行没了」）。现在按实际列宽算，曲名/进度条下限压到 4/2 列，右侧标签从尾巴往后丢
  - 评论每条固定 3 行，可视条数却写死 12 条（=36 行）——24 行的终端里页脚「Esc 关闭」被裁到屏外，看着像这个弹层没有退路。现在按 `listHeight()` 推，并把 `pageSize` 接给游标（`PgUp/PgDn` 整页挪，不再一格一格按）；列表页同样补 `pageSize`
- **分页诚实**：`useList` 的游标从前在上游不回游标时回退成「页序 +1」——而这些源的 `cursor` 全是**偏移量**，于是 `count=50` 的第二页变成偏移 1，整页和第一页重复；`hasMore` 也不管游标有没有真的前进，`L` 按下去行数不涨也不报错，看着就是坏了。现在游标只照上游回传的来，`hasMore` 要求它真的挪了位
- **`truncate` 白丢一个字**：判据写成 `used + w > width - 1`，正好等宽的串也会被砍掉最后一个真字换成 `…`——曲名、队列行、播放条全都少一个字。现在放不下才补省略号，并且退到真腾得出那一列为止
- **第一次起播不再冻一下**：`mpv --version` 探测从 `spawnSync` 改成构造期异步发问、`start()` 只读结果（探到过才拦，没探完当可用——真起不来由 `spawn` 的 error 报同一句话）
- **强退不再在 `/tmp` 攒下 mpv 的 socket**：`src/core/mpv.ts` 的 `exit` 兜底原先只 `SIGKILL` 子进程，不管它那条 `--input-ipc-server`——被 `SIGKILL` 的 mpv 来不及自己摘，而 `child.on('exit')` 里那笔 unlink 在这个时机根本跑不到（本机实测攒过 7 个 `qishui-tui-mpv-*.sock`）。现在 `trackChild()` 连着 socket 路径一起记（`Map<child, socket>`），兜底里杀进程的同时把它摘掉；正常曲终那几条路径原本就摘，行为不变
- **杂项**：`Loading` 的转圈 effect 漏了依赖数组——每次重画（播放条 400ms 一跳、鼠标事件、resize）都重建计时器把 80ms 相位归零，渲染比 80ms 密时转圈整个停住；次要文字不再裸写 `'gray'`（收进 `COLOR.muted`，`borderColor` 也要着色而 `dimColor` 给不了）；帮助页与搜索页把键位讲清楚（补 `PgUp/PgDn` 一行，退出写明「Ctrl+C 连按两次」，不再让人以为单按 `q`/`Ctrl+C` 就退）；队列页 `d` 移出曲目给一句 toast——删掉的如果正在播，界面会变成下一首，不说一句分不清是删掉了还是坏了

- **设置页能选缓存容量档位、淘汰策略，并显示「已用 / 上限」**
  - **为什么**：`maxMediaBytes` 从前在 TUI 是「只读」项（只有布尔和 `defaultRepeat` 能 Enter 改），容量看不见也调不动
  - **做法**：缓存一节加「容量」行（`已用 X / 3G（60%）`，不限制直说，超限再写 `超 Y`）与一条「按上限清理媒体」（确认框里说明按哪个策略、正在播的那首不动，toast 报释放量）；`cycleConfig` 的枚举特例换成 `ENUM_ORDERS` 表（`defaultRepeat` + `mediaEvictPolicy`），`maxMediaBytes` 走 core 的 `nextMediaCapacityTier()` 循环 2G→3G→4G→5G→10G→不限制；`formatConfigValue` 的布尔判定从硬写四个键名改成 `typeof === 'boolean'`
  - **边界**：档位与策略的中文词全部来自 core（`mediaCapacityLabel`/`mediaEvictPolicyLabel`），界面仍是 ASCII + 汉字，没引入进度条或装饰符号

  - 按下去走新的 `toggleTrackLike`（与菜单那条「我的喜欢（切换）」**同一条路**）：云端走 `library.like/unlike`（需登录，未登录只 toast）、本地文件走 `local.toggleLike`（匿名可用），成功后就地翻 `TrackData` 水印再 `ui.bump()`，两颗按钮文案同步翻转

- **封面支持不支持，改成开机问一次（不再拿环境变量猜）**（`ui/termProbe.ts` + `ui/caps.ts`，`cli.tsx` 在 `render()` **之前**问完）
  - **原来**：`coverMode()` 只认 `KITTY_WINDOW_ID` / `TERM` / `TERM_PROGRAM` 三个变量。两头都错：**漏掉**了同样实现 kitty 图形协议 + unicode 占位符的 ghostty / contour / rio / st-graphics（一律退去画半块）；**认错**了 tmux / zellij——`KITTY_WINDOW_ID` 会透传进会话，可图形报文被 mux 吃掉，占位符没人解，界面就是一屏 `U+10EEEE` 残字
  - **现在**：一次写三条查询——kitty 的**查询动作** `ESC_G…a=q,t=d,f=24;AAAA ESC\`、`ESC[>q`（XTVERSION 报牌子）、`ESC[0c`（DA1）。规范把 DA1 当**最后一条**回音，所以它同时是「会不会解 Sixel」和「回音读完了、可以收工」的信号：kitty 实测几十毫秒收工，完全不答的终端只付一次 300ms。选路 = `QISHUI_TUI_COVER` 强制 > 探到 `kgp` 就贴原图 > **压根没探**（非 TTY）才退回环境变量表 > 半块
  - **`a=q` 证明不了占位符能力**（规范里没这一项，占位符是 kitty 0.28 才加的），所以 `konsole` / `warp` 这两个答查询但只实现了旧协议的牌子在 `OLD_PROTOCOL_BRANDS` 名单里挡回半块；名单外「答了查询但牌子未知」的照规范放行——这次放宽收益的来源
  - 探测结果放模块单例（`setTermCaps`/`termCaps`）而不是 React context：`ui/cover.ts` 要能在离线单测里被喂假能力
- **曲目详情页有封面板了**（`screens/TrackDetail.tsx`）：`2N × N` 格、`N = clamp(4, 8, (行数 − 8)/3)`（半块路低于 4 行糊成一片，所以有下限），宽到放得下就左封面右文字两栏（文字栏至少 24 列），窄了封面单独一行；拿不到就 `onEmpty` 整块收掉。与「听歌」页共用同一套 `Cover`
- **迟到的终端回报报文不再打进界面**（`ui/reports.ts`，`ui/keys.ts` 与四处文本输入接上）：慢终端把回音落在 ink 接手之后时，整串会当按键交给每个活跃 handler（搜索框里凭空多出 `?62;4;18c`）。**PTY 实测的坑**：ink 会把一条 APC/DCS 切成好几个事件**并剥掉开头的 ESC**（`_` → 正文 → `\`），所以「按完整报文匹配」根本不存在——只有形状没人敲得出来的（DA1/DA2 整条、带 ESC 的完整报文）永久剔，被剥成 `_` `P` `\` 的碎片只在**探测没读到 DA1** 时开的 5 秒窗口里吞，且正文开头还得对得上回音形状（`Gi=<数字>` / `>|`），对不上就当场收场把字还给人。真终端都答 DA1 → 窗口根本不开

### Fixed

- **kitty 贴出去的图从不删除**：`coverId` 由 url 推，每换一首歌就是一个新 id，久听下来终端里攒着几十张原图。现在 `kittyDelete(id)`（`a=d` + `q=2` 静音，别把错误回音打进输入框）按 **id 引用计数**发——封面与别处共用同一张图时只删一次，最后一处卸载才真删（`Cover.tsx` 换图 / 卸载走 acquire/release）
- **封面每次重画都回源打 CDN**：core 早就把封面落在 `~/.qishui/cache/tracks/<id>/cover.jpg`，TUI 看不见，于是播放中每换一次尺寸就多一次下载。现在 `Cover` 收 `cacheKey` + `load`（`core.media.cachedCover(id)`，**不走** `readMeta`——那个要求 `meta.audio.file` 存在，只有封面没音频的条目也得认），命中就不发请求；内存 LRU 从 16 张提到 32 张（封面位从 1 处变 2 处、尺寸又随窗口变）

### Fixed

- **`[再来一批]`（含「把当前这一档再 `Enter` 一次」）不再连着跳歌**：现象是刷出全新的 6 首后「刚下载完就切下一首、又立马切第三首」，而且常常不从第一首开始。**改在 core**（`qishui-core` 的 `QueueBook.open()`/`resetPlayer()`，见 core `CHANGELOG.md`）：refresh 先 `player.clear()` 回到 `idle`——这一侧现有的 `sink.stop()` 因此把还在响的 mpv 停掉，新一批再从第一首干净起播，上一首的退出/收尾不会连着推走头两三首。TUI 代码不变，只把这页的口径写进注释与文档（`DESIGN.md` / `README.md`：`[再来一批]` = 整台重来，`↓` 手动要的下一批与自动补批仍是只往队尾追加）

- **听歌页右栏：刚启动点队列没反应，点谁也不等于播谁**
  - **症状**：起来后鼠标点右栏那几行曲目，什么都不发生；有时播的是隔壁那首。焦点挪到内容区（`Tab`）之后又像是好了
  - **根因 1（点了没反应）**：队列行 / 歌词行 / 模式行的鼠标 handler 全挂在 `active` 上，而 `active = ui.focus === 'content' && !overlay`——启动时焦点默认在**侧边栏**（`ui/context.tsx`），整页的点击与滚轮根本没接。列表页早就是另一套写法（`List.tsx` 的 `mouseActive`：鼠标不吃键盘焦点，点完再把焦点交给内容区）
  - **现在**：听歌页的鼠标一律按 `!ui.overlay` 门控，点下谁就把焦点交给那一栏（`takePane`），与列表页同一口径；键盘照旧只认 `active`
  - **根因 2（播成隔壁那首）**：点行传的是界面快照里的**行号**，而队列会在你点下来之后变（补批往尾挂、移除往前挪）——行号一挪，播的就是原来那一号位上的另一首，且永远不知道它已经不在了。现在走 core 新加的 `player.playQueueTrack(id)`：按 id 找，找不着给一句「这一首已经不在队列里了」，不静默（`Listen.tsx` 点行与行菜单「立即播放」、`Queues.tsx` 行菜单同改）
  - 「从队列移除」仍按行号（它删的就是眼前这一行，没有「过期快照播错歌」的问题），没跟着改
- **封面真的画得出来了（之前一张都不出）**
  - **症状**：听歌页封面位置一片空白，等多久都不出图；有时整个界面像卡住
  - **根因 1（主因）**：kitty 路的 chafa 尺寸写死成 `--size 256x256`——那个数的**单位是格**，chafa 按 10×20 px/格 换算，于是每张封面都解成 2560×2560 的 RGBA、base64 三十多兆；终端要么噎住、要么把这次传输丢掉，图自然不出来
  - **根因 2**：分块传图把 `a=T,f=32,s=…,U=1,i=…,c=…,r=…` 这组 key 每块都重发了一遍（chafa 自己的输出只在第一块带 key）——续块被当成一次新的传输，攒起来的图挂不到占位符上
  - **改法**：尺寸跟着占位格走（`--size ${cols}x${rows}`，上限 `60x30`）并加 `--stretch`（源图正好铺满这块格子，方形封面不压扁）；分块只有第一块带 key、续块只留 `m`。载荷从 35MB 降到 200~300KB；单测加 `kittySizeArg` 与「只有第一块带 key」两条
  - **同时**：没封面（`coverUrl` 为空）或拉不到图时**不再占位置**——那一块整块收掉、行数还给歌词（原来画一块等高的 `[封面]` 空白，看着就是「没渲染出来」）
- **resize 之后版面会自己适应了**（原来要等下一次按键/播放进度刷新才跟上）
  - **症状**：把终端拉窄（比如 100 → 60 列），播放页还是按 100 列排的——两栏布局不变、右侧队列栏被挤出屏幕；拉高/压扁同理（歌词窗口、列表窗口、提示行还是旧行数）
  - **根因**：ink 收到 `SIGWINCH` 只 `calculateLayout()` + 重绘，**不重渲染 React 树**；而各屏的窗口高度/列宽都是渲染期从 `stdout.rows`/`columns` 算进 JSX 的（`ui.rows`/`ui.columns` 一次读定），所以 yoga 重排了、数字还是旧的
  - **改法**：`ui/context.tsx` 加 `useTerminalSize()` —— 订阅 `stdout` 的 `resize` 把尺寸放进 state（值没变就不重渲染），整棵树跟着重排一次；`useFullscreenRows()` 仍负责「首帧别按旧行数写 yoga」，两层各管一件事（`README.md` §尺寸/备用屏）
  - 播放页的 `SPLIT_MIN` 单栏/两栏切换是这条 bug 最直观的一处，现在由 `test/tui.test.ts` 的 resize 用例钉住（缩 / 拉两个方向都验）；原有的「resize 后画面收敛到新行数」那条同时改成看最后一个 `ESC[2J` 之后的帧（不再拿「含『搜索』的帧」当锚点——60 列下侧栏已经收成单字「搜」）

### Fixed

- **登录成功后登录态不刷新**：三处叠在一起——① 弹层原来自己轮 `status()`，看到 confirmed 后再补一次 `qr.wait()`「让它走完入库」，而入库只发生在 `wait()` 里、`wait()` 又重问一次上游，二维码在登录完成后常被上游判成 expired/unknown，于是谁也没入库（toast 报「登录成功」，顶栏/侧边栏/账号页照旧未登录）；现在入库由 core 在观测到 confirmed 的那次 `status()` 里做完，弹层不再多问一次（详见 core 同条）。② 登录态改成**事件驱动**：`core/context.tsx` 订阅 `account-changed`，登录/切号/登出/`me()` 事后补全身份都会顶起 `sessionRevision` 让界面重读，不再依赖某个入口自己记得 `bump()`。③ 列表页 `useList` 的重取依赖里没有号（只认 `source`），匿名时打开的「随便听听/榜单」登录后仍是匿名内容——`activeUid` 现在进了依赖。附带：`membership:`/`library:` 的取数 key 补上登录与否（`GetMyInfo` 失败、uid 一直 undefined 时也能触发重取），顶栏/侧边栏/账号页在身份未知时显示「已登录（身份未知）」而不是 `undefined`。④ 出错不再只当「网络抖一下」：轮询/入库一抛就显式打出「登录流程出错（仍在重试）：<原因>」——以前入库失败会被静默吞掉，界面看着像还在等扫码，其实是永远不会成功
- **登录流程的出错不再被当成「网络抖一下」吞掉**：轮询/入库一旦抛错，弹层显式打出「登录流程出错（仍在重试）：<原因>」并继续轮（core 会自己补做入库）。原来一律静默记进 `error` 又不显示来源，入库真失败时界面看着像「还在等扫码」，是「扫成功了却什么都没落盘」最难查的那一段
- **按键冲突（ink 的 `useInput` 把每次按键发给所有活跃 handler，没有消费语义）**：账号入口只看 `0`（原先 `0`/`L` 双入口——`L` 同时被列表页当「加载更多」，两处会一起触发）；新建歌单用 `N`（`n` 是全局「下一首」）
- **帮助弹层在小终端上被裁掉顶部**：弹层内容是居中排的，超过终端行数时 yoga 会把上下一起截掉（`导航` 分组整段看不见）。现在正文走滚窗，任何行数都看得全
- **`process.exit` 时残留 mpv**：播放中直接退出（`q`/Ctrl+C）会留下跑到曲末的 mpv 子进程（实测干扰到 CLI 的「无残留进程」断言）；现在退出钩子兜底收掉
- **频繁切歌会同时响多个 mpv**：`AudioSink.start()` 原来先 `await this.stop()` 再起新的，快速连按切换时两次 start 会交错（旧的还没收完新的已起），同时留下多个 mpv 一起出声。现在 start 第一件事是**同步** `terminate()` 上一首（SIGKILL + 清 socket）再起新的，IPC 连接回来时用 generation 校验防止把旧 socket 挂到新进程上；实测并发 10 次 start 后只剩 1 个 mpv，stop 后归 0
- **播放进度/歌词跟着整曲时长走（试听片段下全错）**：分享页给的是试听片段（`演员` 整曲 4:21、实际只 0:52，且从 208.9s 起），原来进度条按整曲元数据画、歌词从 0s 对，播几秒就不同步。现在订阅 core `source` 后开 IPC 每 400ms 读 mpv 的 `duration`/`time-pos`：真实时长喂回 `player.setDuration()`、真实位置纠偏 core 时钟，曲终由 mpv EOF 或时钟先到推进（`repeat` 模式仍由 core 处理）；歌词按片段起点偏移

### Fixed

- **resize 时闪一下**：一帧全屏内容改动就是 `clearTerminal` + 重画一次，而一次 SIGWINCH 原来要画两帧——ink 自己那帧还按旧行数排版，我们 setState 触发的第二帧才纠正（PTY 实测相差 4～13ms）。现在宽度走 `width="100%"`（ink 自己就重算对），高度由 `useFullscreenRows()` 用 `prependListener` 抢在 ink 的 `resized()` 之前把新行数写进 yoga，**一次 resize 只剩一帧**（全屏重绘次数实测 2 → 1）
- **resize 把用户的滚动历史抹掉**：`cli.tsx` 现在在 TTY 里先切备用屏（`?1049h`），退出时 `?1049l` 还原；ink 满屏帧的 `clearTerminal` 带 `3J`（清回滚），留在主屏打就会连带清掉用户自己的历史。非 TTY 不切
- **resize 后布局错乱**：`width={stdout.columns}` / `height={stdout.rows}` 是渲染时烤进节点样式的数字，而 ink 的 `resized()` 只重算 yoga 布局、不重渲染 React 树，改终端尺寸后就停在旧宽高（错位、顶出多余行）。改为尺寸自己维护（`useFullscreenRows()`：首帧行数进 JSX + `prependListener` 写 yoga），底栏再固定成一行（两侧 `truncate-end` 可收缩，窄终端截断不换行）；PTY 实测 100×30→40×10→22×6 帧行数恒等于终端行数、文本仍居中，resize 后鼠标命中也照常（库的 bounds 缓存 16ms 到点自复）

- **`pnpm run tui` 跑完不退出**：入口原来只 `render(<App />)`，没等 ink 收尾。改成 `const { waitUntilExit } = render(<App />)` + `await waitUntilExit()`
- **非 TTY 直接崩溃**（`Raw mode is not supported on the current process.stdin`）：`useInput` 现在按 `isRawModeSupported` 关活。注意 ink 的判断是严格的 `options.isActive === false`，而管道下 `isRawModeSupported` 是 `undefined`，所以要写 `Boolean(isRawModeSupported)`
