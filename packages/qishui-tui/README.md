# qishui-tui

汽水音乐的**终端 TUI**，基于 [ink](https://github.com/vadimdemedes/ink)（React → 终端渲染），跑在 `qishui-core` 之上：**左侧边栏导航 + 通用列表页 + 播放条 + 歌词/评论覆盖层**。页面结构见 [`DESIGN.md`](./DESIGN.md)，可用数据见 [`DATA_TYPES.md`](./DATA_TYPES.md)。

```bash
pnpm run tui:build                                  # = pnpm --filter qishui-tui run build
pnpm run tui                                        # = node packages/qishui-tui/dist/cli.js
pnpm --filter qishui-tui run test                   # vitest（全程离线，不碰上游）
QISHUI_TUI_STUB=1 pnpm run tui                      # 骨架模式：只画外壳，不建 core
```

### 扫码登录的终端二维码

`core.login()` 交出的是 `https://bff-pc.qishui.com/…` 扫码深链，`src/overlays/Login.tsx` 用 `qrcode-terminal` 把它画成终端二维码（**只能用「汽水音乐」App 扫**，抖音扫不出来），并每 2 秒轮询 `qr.status()` 显示「待扫码 / 已扫码待确认 / 已过期」。`status()` 观测到 confirmed 时 core 已经把会话入库并激活，弹层只管关掉自己 —— 登录态之后由 core 的 `account-changed` 事件驱动刷新（`src/core/context.tsx` 订阅它顶起 `sessionRevision`，各页面因此重读），不靠弹层自己记得重绘。

识别快慢的两处处理：

- **静区**：`qrcode-terminal` 贴着边画、一格白边都不给，App 要对焦很久才认得出（官方那张 PNG 是带 4 模块白边的）。这里画完自己补一圈 4 模块留白再上屏，终端太矮时退成不带留白的紧凑图。
- **官方图片兜底**：core 把上游 `data.qrcode` 那张 PNG 落成临时文件（`login.qrImage`，0600），弹层在码下面一行显示「识别慢就扫官方二维码图片：<路径>」，点开就能拿手机扫它。

版面按行数自适应：一行标题 + 二维码 + 一行深链 + 一行图片路径 + 一行键位（码本体 22 行 × 43 列，带静区 30 行）。

- `≥34` 行：带 4 模块静区的**整图**（好识别，等价于 CLI `qishui login` 那张）；
- `26~33` 行：不带静区的紧凑版（还是完整的一张码，只是识别会慢些）；
- 再矮、或宽度不足 45 列：不装作画得下，改为「终端太矮/太窄 + 深链文本」，改窗口大小后按 `r` 重画；实在嫌慢就直接扫上面那行给出的官方 PNG。

写操作口径沿用仓库约定：无会话只在本地拦下并提示怎么登录，不去撞上游的 `1000016`；「不可播 / 未验证」照实显示，不画结论。

**出声**走外部播放器：core 的 `Player` 只维护状态机，`src/core/mpv.ts` 在 `source` 事件上把解析好的播放源喂给 **mpv 子进程**（JSON IPC 做暂停/seek/音量），进程退出时兜底 `SIGKILL` 收尾不留孤儿进程。切歌时 `start()` 会先**同步**收掉上一首再起新的（同一时刻只有一个 mpv 在响）。进度以实际音频为准：每 400ms 经 IPC 读 mpv 的 `time-pos`/`duration`，真实时长喂回 `player.setDuration()`、真实位置纠偏 core 时钟（试听片段常比元数据时长短得多）。换播放器：`QISHUI_PLAYER=ffplay`、无音频设备时 `QISHUI_MPV_ARGS=--ao=null`。

**歌单写操作**统一收在 `src/ui/playlistActions.ts`（新建/改名/删除/移出曲目）：「我的」页与歌单列表页共用同一套流程——登录前置检查 → 弹层 → `core.library.*` → toast；改名会先读回歌单，把 `description`/`is_private` 一起带上，避免上游把没传的字段清空。

## 播放队列（`Q`）：一份队列一个来源

播放器同一时刻只播一份队列，但**队列不止一份**——推荐 / 我喜欢 / 每张歌单 / 临时各自是独立的一份，
各自记着播到第几首。听到一半去点一张歌单，推荐那条流不会没；切回来接着上次那一首。
实现在 core（`core.queues`，`packages/qishui-core/src/player/queues.ts`），TUI 只负责打开 / 切换 / 显示。

| 队列 | 谁产生 | 曲目 | 策略 |
|---|---|---|---|
| 推荐 | 听歌模式（场景 / 推荐 / 熟悉 / 新鲜） | 上游每次一小批（实测 6 首） | **只往后追加**：听过的不删、跳播也不动已经排好的那些（每首的序号不变，右栏按固定 10 行窗口滚着看）；后面剩 ≤2 首补**一整批**（给几首收几首，不截断），停在队尾按 `↓` 还能主动要下一批；**顺序播、不随机**；队列播完自动重启续批，连续 2 批失败才停 |
| 歌单 | 每张歌单一份（本地歌单也算） | 整张 | 顺序播；切走再切回来接着上次那一首 |
| 我喜欢 | 「我喜欢的音乐」/ 本地喜欢 | 全部 | **随机** |
| 临时 | 搜索 / 榜单 / 专辑 / 艺人 / 首页推荐块 | 这一次点播的那一批 | 顺序播；**每次点播整队替换上一批**（临时不留旧账） |

- 列表页的「播放这首」= 「把这首所在的那份队列切到前台」，不是「覆盖播放器队列」；歌单行 / 专辑行的
  「播放整张」自己带队列（不落到当前页那份）。翻译在 `src/ui/queues.ts`。
- **侧边栏第 4 项**直达播放队列页；`Q` 是压在当下页之上的同一页（`screens/Queues.tsx`）：上半「队列」段切 / 收起队列，下半按播放顺序列当前队列曲目；
  在播那份标「（在播）」、推荐队列标「自动续批」。**弹层已经删了**——弹层有最小宽度，窄终端会溢出。「听歌」页右栏头的 `[切换队列]` 弹层也能切（`(x)` 标当前那份，末尾一条进这页管理）。
- **书架持久化**（core 的 `QueueBook`，落 `<dataDir>/queues.json`）：变化后 300ms 防抖原子写、退出前 `flush()` 收尾；重启后每份队列还在、还记着上次播到第几首，
  推荐队列连档位与自动续批状态一起恢复（`load` 闭包没法序列化——歌单/喜欢没取完的那部分要回列表页再点一次）。
- **上限 10 份**（core 的 `MAX_QUEUES`）：每张歌单、每档听歌模式各占一份，听久了会攒出几十份；超了就在开新队列时
  **收起最久没用过的那份**（在播的永不淘汰）并 toast 一句，页面标题里显示 `N/10`。
- 换号（`0` 页切号 / 登录 / 登出）书架整份清空：我的喜欢 / 我的歌单换了号就是另一套。

## 封面渲染（「听歌」页 + 曲目详情）

按终端能力自动选路，`QISHUI_TUI_COVER=kitty|ansi|off` 可强制（**强制时连探测都不发**，省掉那次启动停顿）。

- **能力靠开机探测，不靠环境变量猜**（`ui/termProbe.ts`，在 `render()` **之前** await 完，所以不会和 ink 抢 stdin）：
  一次写三条查询——kitty 图形协议的**查询动作** `ESC_Gi=<固定 id>,…,a=q,t=d,f=24;AAAA ESC\`、
  `ESC[>q`（XTVERSION，回 `DCS >|<牌子> ESC\`）、`ESC[0c`（DA1）。规范把 DA1 当**最后一条**回音，
  所以它既是「会不会解 Sixel」也是「回音读完了、可以收工」的信号；完全不答的终端只付一次 300ms。
  结果写进模块单例 `ui/caps.ts`（`coverMode(env, caps = termCaps())`），**探到才认**：
  `ghostty`/`contour`/`rio`/`st-graphics`/xterm.js 系以前被环境变量表漏掉，现在贴原图；反过来
  `KITTY_WINDOW_ID` 透传进 tmux/zellij 但图形报文被 mux 吃掉的那种，探测收不到回音 → 退回半块，
  不会再画出一屏 `U+10EEEE` 残字。环境变量表只在「压根没探」（非 TTY）时兜底。
- **有图形协议**（`caps.kgp`）：`ui/cover.ts` 用 `chafa` 把任意格式的封面解成**原始 RGBA**，走 kitty 图形协议把
  **原图**贴进来（虚拟放置 `U=1`），正文里只画 `U+10EEEE` 占位符（前景色 = 图片 id）。占位符是普通文字，
  ink 每帧整屏重画时图跟着占位符走、不会被擦掉——这是唯一能和 ink 的整屏重绘共存的贴图方式
  （直接定位贴的 Sixel/iTerm2 图会被下一帧差异擦掉，所以**只有 kitty 路贴原图**）。
  三个必须守住的细节：传图尺寸**跟着占位格走**（`--size ${cols}x${rows}`，几十兆的载荷会把终端噎住、图反而出不来）；
  分块**只有第一块带 `a`/`f`/`s`/`v`/`U`/`i`/`c`/`r` 这组 key**、续块只留 `m`（重发 key 会被当成一次新传输）；
  图片**要按 id 引用计数删除**（`kittyDelete` + `q=2` 静音），不然久听会在终端里攒下几十张原图。
  `a=q` 只证明「会答查询」，规范里没有任何字段报**占位符**能力（那是 kitty 0.28 才加的），所以
  Konsole / Warp 这类旧协议实现在 `OLD_PROTOCOL_BRANDS` 名单里挡掉，让它们走半块。
- **没有协议**：用 `chafa` 输出彩色半块 `▄`（`--format symbols --colors full --symbols vhalf --stretch`），解析成每格的
  fg/bg，再用 ink 的 `<Text color backgroundColor>` 画（同色的连续格并成一个 span）。
- 两条路都**只依赖本机 `chafa`**；拉图 / 解码 / 超时一律静默降级——**没封面（或拉不到）就整块不占位置**，行数还给
  歌词，不留一坨空白。**字节优先取本地**：core 早就把封面落在 `~/.qishui/cache/tracks/<id>/cover.jpg`，
  页面传 `cacheKey`/`load`（`core.media.cachedCover(id)`）就不再去 CDN，本地没有才回源；内存 LRU 32 张，尺寸变了才重解。
- **回音晚到的兜底**（`ui/reports.ts`）：慢终端把回音落在 ink 接手之后时，整串会当按键交给每个活跃 handler。
  ink 还会把一条 APC/DCS **切成好几个事件并剥掉开头的 ESC**（`_` → 正文 → `\`），所以「按完整报文匹配」不存在：
  只有形状本身没人敲得出来的（DA1/DA2 整条、带 ESC 的完整报文）永久剔；被剥成 `_` `P` `\` 的碎片**单独看就是正常的字**，
  只在探测没读到 DA1 时开的 5 秒窗口里吞，而且正文还得开头对得上回音形状（`Gi=<数字>` / `>|`）才对不上就当场收场。
  真终端都答 DA1 → 窗口根本不开，`_` 照旧是普通输入。
- 单测 `test/cover.test.ts` / `test/termProbe.test.ts` / `test/keys.test.ts` 只碰纯函数与假流（能力判定、
  占位符网格、chafa 尺寸/传图分块/删除转义与引用计数、本地字节优先、探测解析与假流收工），不拉图、不跑 chafa、不打上游。

## 界面口径（只用 ASCII + 汉字）

界面不掺表情符号和装饰图形——`▶⏸ 🔊 ↻ ⇉ ♥ ★ ▍ ✕ ○● ⠋ ✓` 这类一律不用，改成中文词与 ASCII：**状态/模式是词**（`播放` `暂停` `载入` `循环:关` `随机:开` `音量:60` `静音`），**选中与当前行是 `>`**，**错误是 `x`**，**加载转圈是 `| / - \`**。

理由不是审美：同一个码位在 emoji 呈现 / 中文字体下经常占 2 格，`displayWidth()` 估不准，播放条和列表的列就会跟着错位；纯字符与汉字怎么都只占 1 格（汉字固定 2 格）。唯一保留的图形是进度条的 `━●─`——它本身就是终端图形元素，而且每格只画它一个字符。

- 词表集中在 `src/ui/theme.ts`（`SELECT_PREFIX`/`CURRENT_PREFIX`/`ERROR_PREFIX`/`NO_TRACK_TEXT`），标签集中在 `src/ui/playMode.ts`，颜色集中在 `COLOR`——加控件时从这三处取，别在页面里裸写 `'cyan'` 或某个符号。
- 播放条因此改成**按宽度收起**：中文标签比图标宽，装不下就按优先级从尾巴往后丢（队列位置 → 随机 → 循环），时间与音量保底；被丢的开关在「听歌」页的正在播放区里常驻一排，功能不缩水。
- PTY 单测的锚点跟着换了（`关键词 abc`、`>最近播放`），输入行的唯一标识是收起输入后的占位 `（按 / 继续输入）`——侧边栏和面包屑里都有「搜索」二字，不能拿它当行锚点。

> ink 的 `useInput` 把每次按键**发给所有活跃 handler**（没有「消费」语义），所以同一个键不能两处都用：「我的」（原账号页）只留 `0`（`L` 让给列表的「加载更多」），新建歌单用 `N`（`n` 是全局下一首）。加键前先看 `App.tsx` 的全局键表。**行操作因此不再各占一个散键**——全部收进 `Enter` 打开的操作菜单，一个键管五种行类型，键位表从十来行缩成一行。
>
> 命令类按键一律走 `ui/keys.ts` 的 `useKeys`（= ink 的 `useInput` + **多字符输入按字符拆开派发**）：ink 把一次 read 的整串交给 handler，人快手连按 `jj`、或粘贴一段文字时拿到的是 `'jj'`/`'晴天'`，而命令 handler 比的都是 `input === 'j'`——不拆就是「按了两下、列表没动」。文本输入处（搜索框、评论、歌单名）仍用 `useInput`，它们本来就按字符收下。

## 鼠标

报文解析交给 `@ink-tools/ink-mouse`（底层 `xterm-mouse`，SGR 编码、坐标 **1 基**），`src/ui/mouse.tsx` 只做三件薄事：把事件换算成**盒内 0 基行列**、把库的**闭区间**命中收成**半开区间**、`Pressable` 省掉每处手写 `useRef`。

能点的：侧边栏导航、通用列表/分区条目的每一行（**单击直达**：列表页点一行 = 直接开这一行的操作菜单，弹层/条目页点一条 = 跑它的 `Enter`。开菜单与开弹层都不写任何东西，写操作还得在里面再选一次，删歌单另过确认框；滚轮只挪游标）、操作菜单/加入歌单/举报/评论的列表行、播放条的每个控件（播放/暂停、进度条、`循环:` `随机:` `音量:` 三个词标签，曲名进「听歌」页、队列计数进播放队列页）、「听歌」页的模式档 / 进度条 / 歌词行（点一句跳到那句）/ 封面与曲名 / `[上一首] [播放] [下一首] [喜欢] [操作] [音量:] [循环:] [随机:]` 按钮（`b` 可用键盘选中它们、`Enter` 按下） / 「艺人 · 专辑」行、播放队列页的队列行与曲目行（点一行切过去 / 播它）、顶栏面包屑与账号徽标、搜索的分类 tab、输入行与联想词行、歌单广场的分类 tab 与「加载更多」、确认框的 `[确认]` `[取消]`、新建歌单的私密勾选、评论的选块与「写评论」、帮助正文行、登录页的「重新获取 / 取消」。落在内容区的一次点击/滚动还会顺手把焦点交给内容（等价 `Tab`）。

**点击穿透这一道闸**：弹层正画在指针下方，双击的第二下（`SectionView` 挂载后 350ms 内的点击）只挪游标、不执行条目——否则「点一行开菜单」顺带就把菜单第一项跑了。键盘 `Enter Enter` 不受这道闸影响（那才是主路径）。

四条口径：

- **接缝归属**：库判定命中用 `left..right` 闭区间，而 `right = left + width`——宽 16 的侧边栏会盖到第 17 列，而第 17 列正是内容区第一列，一次点击两个 handler 都跑。`hitTest()` 收成 `[left, right)` / `[top, bottom)`，接缝列只给真正的持有者（单测里那条「点第 17 列不切页」就是守这个的）。同理，**同类型的 handler 不要挂在父子两个盒子上**：库会把一份报文发给每个命中的 handler，父子都注册就双跑；现在的接法是「一个盒子管一段行」，按钮之间都是兄弟盒。
- **四个模式全开且运行期不关**（`?1000` 按键/滚轮 + `?1002` 拖动 + `?1003` 移动 + SGR `?1006`）：曾经为了省 stdin 流量在 `MouseSetup` 里补一条 `\x1b[?1003l\x1b[?1002l`，结果在 VTE 系终端（gnome-terminal 等）上**把点击整个废掉**——只开 `?1000` 时终端把界面当成拖选文本区，光标停在 I 型、点下去什么都不报进来。代价是**终端原生的拖选复制被接管**——要复制请按住 `Shift` 拖选，或者干脆 `QISHUI_TUI_MOUSE=0` 启动（彻底不接管鼠标）。退出（含被强杀，走 `process.on('exit')` 兜底）会把四个模式一并关掉，不留鼠标模式。
- **弹层盖住的那一层不接鼠标**（`MouseBlock`）：底层页面在弹层开着时**不卸载**（要保住已取的数据与游标），但它的布局矩形还在，`hitTest` 照样命中——不挡就是「点弹层的按钮，底下那一行同时被 `Enter`」、滚轮两边一起滚。作用域只包 `BaseLayer`，弹层自己不在这棵子树里，照常接鼠标。
- **鼠标报文也是「输入」**：ink 的 `useInput` 没有「消费」语义，原始报文会同时进按键 handler，所以文输入处过 `stripMouse()`、单键快捷键处过 `isMouseInput()`，否则滚一下轮就往搜索框里塞 `[<64;10;5M`。

不做悬停高亮（要重开 `?1003`）、不做按住拖动 scrub（要 `?1002` + 防抖）；进度条是**点击定位 + 滚轮 ±5 秒**，音量键滚轮 ±5%。`MouseProvider` 的 `cacheInvalidationMs` 设为 `0`：默认 16ms 的盒子尺寸缓存，在「刚点完 → 重排 → 再点」时会拿陈旧矩形判命中。

## 骨架模式（`QISHUI_TUI_STUB=1`）

不创建 core、不连网、不读账号，只画外壳（顶栏标「骨架模式」）。用途有两个：单测做到**完全不碰上游**；改版面时不必等设备身份注册/账号解析。此时各页停在「加载中」是预期行为。

## 尺寸 / 备用屏 / 非 TTY

- **备用屏**：满屏帧必然走 ink 的 `clearTerminal`（`ESC[2J ESC[3J ESC[H`，带清回滚），留在主屏会把用户自己的滚动历史一起抹掉，所以 TTY 里先 `?1049h`、退出 `?1049l`。
- **resize**：ink 的 `resized()` 只重算 yoga 布局 + 重绘、**不重渲染 React 树**，而各屏的窗口高度/列宽（列表窗口、歌词行数、单栏/两栏）都是渲染期算进 JSX 的，光让 yoga 重排改不了这些数。所以分两层：
  - **尺寸进 state**：`ui/context.tsx` 的 `useTerminalSize()` 订阅 resize 把 `columns`/`rows` 放进 state，让整棵树跟着重排一次——这是「内容真的适应新尺寸」的那一步（`test/tui.test.ts` 的「听歌」页 resize 用例盯着它：宽屏画出模式行右侧提示、缩窄后收起）。
  - **首帧高度**：宽度交给 `width="100%"`（ink 自己算对），高度由 `useFullscreenRows()` 用 `prependListener` 抢在 ink 之前写进 yoga 节点，免得 ink 那一次重绘先按旧行数画一帧（实测 `ESC[2J` 次数减半）。
- **窄终端**：`≥72` 列两栏；`48–71` 列侧边栏收成 4 列图标栏；`<48` 列侧边栏隐藏，`Tab` 焦点回导航时以浮层形式弹出（`src/ui/context.tsx` 的 `sidebarWidthFor`）。
- **非 TTY**（管道/CI）：stdin 开不了 raw mode，`useInput` 关活、不切屏、`stdout.rows` 拿不到就让帧按内容收缩，只打一句「非交互终端」后退出 0。

两个坑记在这：①**每条用例起进程后先等 2.4 秒再发键**——冷启动要把 ink（+ react/yoga）加载进来，机器有负载时 1 秒以上是常态，等不够就会出现「点了没反应 / `q` 落在渲染前」的假失败，所以文件里 `vi.setConfig({ testTimeout: 40_000 })`；②**启动页是「听歌」，面包屑第一段也是「听歌」**，拿它反查行号会指到表头，鼠标用例的锚点因此改用「我的」/「本地」。

> 骨架模式下 core 是 `undefined`，所以「登录 / 歌单写操作 / 缓存清理」在单测里只验**界面与本地拦截**（例如 `N` 会提示「core 还没就绪」），不验写入结果——真写入要会话，按仓库约定不跑。
