# qishui-tui 页面设计（侧边栏导航）

> 配套输入：[`DATA_TYPES.md`](./DATA_TYPES.md) —— 现有 API/core 能拿到的**可用数据类型清单**（逐字段 + 来源 + 匿名/登录口径）。

目标：在**已有 `qishui-core` 能力**（不新增上游调用）之上，给终端一个**操作清晰、结构简单**的界面。
导航用**左侧边栏**常驻，一级功能一眼可见、随时可切；详情/播放靠压栈与覆盖层，不挤占侧边栏。

---

## 1. 设计原则

1. **能复用就不新增页面**：core 里绝大多数内容都是「一个曲目列表 + 一段头信息」（榜单/歌单/专辑/艺人/搜索/最近播放/块下钻…），所以只做**一个通用列表页**，用参数区分来源。唯一的例外是「听歌」——上游听歌模式一次只随机回一小批，不是一屏可浏览的列表，所以它是一页「模式单选行 + 正在播放」而不是列表（见 §4.4）。
2. **侧边栏只放一级功能**：搜索、发现、听歌、播放队列、我的、本地、设置。榜单不另起一项——首页榜单块在「发现」里已经摊平；登录/切号也不另起一项——并进了「我的」。详情、播放、登录都是压栈或覆盖，不增加侧边栏项。
3. **状态常驻可见**：侧边栏常驻 + 底部播放条常驻，任何时候都知道「我在哪、在播什么」。
4. **一份数据两条出路对齐 CLI**：列表沿用 CLI 三线表口径，同一个 core 方法喂两个前端。
5. **不替上游下结论**：拿不到地址 / 无权限，就地标「不可播」「未登录」，不静默吞。
6. **只用 ASCII + 汉字**：状态、模式、音量一律中文词（`播放` `循环:关` `音量:60`），选中/当前行用 `>`，错误用 `x`——不掺表情符号和装饰图形（`▶⏸🔊♥★▍` 那类）。理由不是审美：同一个码位在 emoji 呈现 / 中文字体下常占 2 格，`displayWidth()` 估不准，播放条与列表列会跟着错位。词表集中在 `ui/theme.ts`，模式标签集中在 `ui/playMode.ts`；唯一的例外是进度条 `━●─`（它本身就是终端图形，且每格只画它一个字符）。

## 2. 整体框架

```
┌──────────────┬────────────────────────────────────────────┐
│  搜索     /  │  听歌 · 选一个模式 · 随机取一批   Yinx VIP   │  ← 顶栏：面包屑 + 账号
│  发现        ├────────────────────────────────────────────┤
│ |[听歌]      │                                            │
│  播放队列  Q │                                            │
│  我的        │        内容区（列表 / 详情 / 表格）          │
│  本地        │                                            │
│  设置        │                                            │
│              │                                            │
│              │                                            │
│  ──────────  │                                            │
│   未登录     │                                            │  ← 侧边栏底部：登录态
├──────────────┴────────────────────────────────────────────┤
│ 播放 红色高跟鞋 — 蔡健雅  ━━━━●────── 1:02/3:27 音量:60    │  ← 播放条（跨全宽）
│ Enter 播放   a 队尾   A 下一首   l 红心   c 评论   ? 帮助   │  ← 提示行（跨全宽）
└───────────────────────────────────────────────────────────┘
```

> 侧边栏两种标记（都不占背景色）：`|` = **当前所在的页**（焦点挪到内容区后只剩它，照样告诉你在哪一页）；
> `[方括号]`（accent 色）= **光标所在项**。启动时两者都在「听歌」上（`|[听歌]`）。

| 区域 | 内容 | 说明 |
|---|---|---|
| 侧边栏 | 7 个一级项 + 底部账号 | 固定宽度 16 列；最左一列是竖线 `|`（当前页），光标项用带颜色的 `[方括号]` 包起来——**不用反色色块**（整行反色在浅色/透明背景的终端上会糊成一条）；当前页一直保持 accent 色，进详情时也亮着 |
| 顶栏 | 面包屑 + 账号/会员标 | 压栈时显示 `‹ 发现 / 歌单`；宽度紧张时面包屑截断 |
| 内容区 | 当前页 | 见 §4；**选中的行 = `>` 前缀 + 下划线 + accent 色**（不用反色块，行内的在播绿/错误红不会被盖掉） |
| 播放条 | 状态 + 曲名/歌手 + 进度 + 模式 + 音量 + 喜欢 + 来源 | 控件一律中文词（`播放` `音量:60` `循环:关` `随机:关` `喜欢`/`已喜欢`）；一行装不下就按优先级从尾巴往后丢（时间/音量保底，被丢的开关在「听歌」页的正在播放区里常驻可见）。`喜欢` 与听歌页那颗 `[喜欢]` 同一条路（`toggleTrackLike`）。`f`（或点曲名/队列计数）进**「听歌」页**（独立播放页已并入） |
| 提示行 | 只显示**当前页可用**的键 | `?` 看完整帮助 |

### 侧边栏项 → 页面

| # | 项 | 快捷键 | 根页 | 数据来源 |
|---|---|---|---|---|
| 1 | 搜索 | `1` `/` | 搜索页 | `search.*` `suggest` `categories` |
| 2 | 发现 | `2` | 发现页（首页大盘的**内容浏览**：榜单/歌单/专辑/艺人/曲目 + 歌单广场入口） | `discover.home` `discover.playlistSquare` |
| 3 | 听歌 | `3` | 听歌模式单选行（常用三档 + 场景）**+ 正在播放**（曲名/封面/开关/滚动歌词）一页收齐，选模式即起播（场景只在这页处理，发现页不混） | `discover.feedModes` `feedModeTracks` `player` `lyrics` |
| 4 | 播放队列 | `4` `Q` | 书架整页（§4.9）：切 / 收起队列 + 当前队列曲目；**落盘 `queues.json`，重启还看得见** | `core.queues` `player` |
| 5 | 我的 | `5` `0` | 账号 + 我的音乐（登录/切号/登出与收藏/歌单/最近在一页） | `login` `accounts` `useAccount` `membership` `library.*` `history.*` |
| 6 | 本地 | `6` | 本地库一页收齐：本地喜欢 / 本地历史 / 本地歌单 / 音乐文件夹（**不出网、匿名可用**；与「我的」那份云端收藏/歌单是两个真相源） | `local.*` `history.*` |
| 7 | 设置 | `7` / `S` | 设置与缓存（`S` 压在当下页之上，`Esc` 退回；侧栏项直接切页） | `cacheStats` `clearCache` `config` |

> 侧边栏底部那行是**状态**也是入口：未登录显示 `未登录`，登录后显示 `昵称`，点击/`Enter` 进「我的」（账号操作已并在那一页）。
>
> **启动页是「听歌」（第 3 项）**：它是唯一会自己出声的页——core 一就绪就按记住的 `config.feedMode`（没记住过就用推荐档）取第一批并自动起播，播完自动续批。想先看别的页按 `1`/`2`/`5` 就行；`QISHUI_TUI_AUTOPLAY=0` 可关掉自动起播（离线自检、或不想一开就被声音打断）。

### 导航模型

```
侧边栏（常驻，切换一级页）
   搜索 · 发现 · 听歌 · 我的 · 本地 · 设置
        │
        └─ push ─► 列表页 ─push─► 曲目详情
                    ├─ push ─► 播放队列（`Q`：书架切换 + 当前队列曲目）
                    ├─ push ─► 听歌（`f`：正在播放区；已在听歌则退回）
                    └─ 覆盖层：帮助 / 登录 / 加歌单 / 评论 / 操作菜单 / 确认
```

- **压栈的详情/列表**：`Esc` 逐层退回；回到一级页根后按顺序收：焦点在侧边栏 → 交给内容，焦点在内容 → **弹退出确认**（`y`/`Enter` 才真退，`n`/`Esc` 取消）。退出只有两个入口：这个确认弹层，和 `Ctrl+C` 连按两次（单按只响一声；`q` 不是退出键）。
- **焦点区只有 3 处**：侧边栏 / 内容（含搜索输入行）/ 弹层。`Tab`（`Shift+Tab` 反向）在三者间循环，焦点在侧边栏时 `↑↓` 选项、`Enter` 进入、`1..7` 直达。
- **每一级页独立保留自己的浏览位置**：切走再切回来，列表游标与滚动不丢。

### 窄终端适配

- 宽度 ≥ 72：正常两栏（侧边栏 16 列）。
- 宽度 < 72：侧边栏**收窄成图标/首字模式**（约 4 列，如 `搜` `发` `听` `我`），选中项仍高亮。
- 宽度 < 48：侧边栏**隐藏**，按 `Tab` 或 `,` 把焦点交给导航时以浮层形式临时唤出（覆盖在内容上，选完自动收起）。
- 播放条与提示行始终各固定一行、`truncate-end` 不换行（沿用 resize 方案：尺寸进 `ui` 的 state + `useFullscreenRows()` 管首帧高度）。
- **resize 后整页重排**：窗口高度/列宽都随 `useTerminalSize()` 一起更新（单栏/两栏、歌词窗口、列表窗口），见 `README.md` §尺寸/备用屏。

## 4. 各页面内容

### 4.1 搜索 Search（一级）

```
关键词 晴天                                        [清空]
← 综合 · 歌曲 · 专辑 · 歌手 · 歌单 · 视频 →        ← categories()
──────────────────────────────────────────────────────
歌曲
  1  晴天  周杰伦  4:29   7627888436947339298
  2  …
歌手   （「综合」按分组，每组前 3 条 +「查看全部 →」）
```

- 输入中：`suggest()` 联想下拉（防抖 250ms，最多 6 条）；`↑↓` 在高亮里走，`Enter` 或点一下把词回填输入框——**回填不重新联想**，面板原样留着，只有敲键盘才刷新。
- 提交：按当前分类调 `search.search/tracks/albums/artists/playlists`。
- 结果行：`Enter`（或点一下）开**这一行的操作菜单**（`buildRowActions`，与列表页同一条路）——曲目 播放这首/下一首播放/加入队尾/我的喜欢/评论/详情…，歌单与专辑 打开 + 播放整张 + 收藏，艺人 热门/全部歌曲/全部专辑/关注。**Enter 不再直接把第一首播出去**。
- `←/→` 切分类；每组末尾的「查看全部」进对应分类的列表页（20 行/页，滚到底接着拉 —— 上游按类型搜有 `next_cursor`，`all` 的预览组没有）。

### 4.2 发现 Discover（一级）

纵向滚动的「卡片分区」，`Enter` 下钻：

| 分区 | 内容 | 进入后 |
|---|---|---|
| 榜单 | 首页榜单块（名称 + 曲目数） | 列表页 `chart:<id>` |
| 歌单 / 专辑 / 艺人 / 曲目 | 各首页块摊平的行 | 列表页 `playlist:<id>` / `album:<id>` / 详情 / 直接播 |
| 歌单广场 | 入口 | 列表页 `square[:categoryId]` |

- 一次 `discover.home({layout:'grid'})`；首启引导看 `launch().boost.needSet`（有则提示，不强制弹）。
- **听歌模式与场景不在这页**：早期这里有一条「随便听听」和一批 `radio:<id>` 场景条目，跳的都是「电台」列表页——那批接口一次只随机回一小批，不是可浏览列表。现在这一职责整个收在「听歌」页（§4.4），发现页只做内容浏览，不留第二个入口。

### 4.3 榜单（不独立成页，就在「发现」里）

- 首页 `discover_top_song_list` / `discover_track_top_list` 块的每个条目本身就是一个榜单入口（名称 + 曲目数），「发现」页已经把它们摊平成分区条目。
- `Enter` → 列表页 `chart:<id>`（带名次/涨跌箭头：`1 ↑2`、`5 ↓1`、`8 –`）；整榜用 `catalog.chart()`。
- 早期另有一个「榜单」一级页，把同一批块再摊一遍——两个入口一份数据，已删掉那一项。

### 4.4 听歌 Listen（一级）

一页两件事：**上面一行选听歌模式**，**下面看当前这首歌**（曲名 / 封面 / 开关 / 滚动歌词）。
「正在播放」原来另有一个独立播放页（`f` 压栈的两栏页：左曲目信息+歌词、右播放队列），现已并进来——
「现在在听什么」本来就该在听歌页回答，再单开一页只是多一次跳转；队列单独留一个「播放队列」页（侧边栏第 4 项 / `Q`，§4.9）。

```
听歌模式：推荐   推荐  熟悉  新鲜  场景              ← 单行选择（←/→ 挪、Enter 应用）
┌ 正在播放 ───────────────────────────┬ 播放队列 · 推荐  [切换队列] [收起] ┐
│  晴天                               │ >  3 晴天 — 周杰伦          │
│  周杰伦  ·  叶惠美                  │    4 稻香 — 周杰伦          │
│  （封面，拉不到就整块不画）          │    5 七里香 — 周杰伦        │
│  ●──────────────────── 1:02/4:29    │                             │
│  [上一首] [播放] [下一首] [喜欢]    │                             │
│  [操作] [音量:60] [循环:关] [随机:] │                             │
│  歌词                               │                             │
│    上一句                           │                             │
│  > 当前行（逐字高亮）               │                             │
│    下一句                           │                             │
└─────────────────────────────────────┴─────────────────────────────┘
窄屏（内容宽 < 64）：只放一栏，顶上一行 [歌词] [队列]（`t` 或点 tab 换）
右栏可收起（`q` 或点 [收起]）：收起后整栏换成一条摘要带 `播放队列 N 首 · 标题 · 第 k 首  [展开]`，曲目区铺满
```

- **模式单行**：偏好三档（`FEED_PREFERENCE_MODES`：推荐 / 熟悉 / 新鲜，core 常量、不依赖请求）+「场景」（开弹层选，40 多条自带按游标滚动）。`←/→`（`h/l`）挪高亮、`Enter` 应用：偏好档 = 取一批起播，`场景` = 开 `ActionMenuOverlay`。点某一档也是应用。
- 数据来源就一个：`discover.feedModes()`（`preferences` + `scenes`）。取值动作走 `discover.feedModeTracks(ref)`——**两档都打 `FeedSongTab`**：偏好档落 `preference_mode`，场景档落扁平 `feed_preference.scene_mode_id`（早先场景错走 `FeedRadioTracks`，那条路的 `radio_id` 只认电台队列，短数字被忽略、回的是通用池，所以「选日语推中文歌」）。都是一次约 6 首的批次，所以这里不画列表、不分页、没有「加载更多」。
- **模式行右侧按状态给一个动作**：有当前模式 = `[再来一批]`（**整台重来**：走 `open({ refresh: true })`——core 先 `player.clear()` 停掉在播那首（`idle` 会让这一侧把还在响的 mpv 一并停掉），播放列表整队换成全新的 6 首并**从第一首起播**；不清就会「盖」在还在响的旧曲上换，上一首的收尾会连着把新一批的头两三首推过去）；挪到别的档时先显示那一档的**「上次：曲名」**（每档一条推荐队列，切走再切回来接着上次那首，所以能回溯）；否则是一句说明（`内容宽 ≥ 60` 才画，窄屏省掉它、别把模式挤没了）。**没有「停止续播」这颗按钮**——自动补批是这条流的本职，能关的只有「连续几批取不到」那一次（core 自己停并 toast）；要收掉整条流就去「播放队列」页把那份队列收起。**`↓` 到队尾的「手动要下一批」与 core 的自动补批都是只往队尾追加**，不重置、不动在播那首——只有 `[再来一批]` 和「把当前这一档再 `Enter` 一次」是重来。
- **正在播放区**：曲名（点它 = 当前曲目的操作菜单）/ 艺人·专辑（点它进专辑或艺人热榜）/ 封面 / 进度条（点按定位、滚轮 ±5 秒）/ `[上一首] [播放] [下一首] [喜欢]` / `[操作] [音量:] [循环:] [随机:]`（都是可点按钮，合成一份 `controls: ChipSpec[]` 再切成两排渲染；一行装不下时按优先级从尾巴丢——`[操作]` 与 `音量` 是这页唯一的入口，排前面）。**`[喜欢]` / `[已喜欢]` 跟着当前曲目状态出文案**（`trackLiked` 先看 `state.isCollected` 水印、退到内存里那份收藏清单，都没有就按未喜欢；磁盘文件读 `core.local`），按下去走 `toggleTrackLike`（与菜单那条「我的喜欢（切换）」同一条路：云端需登录、本地文件不需登录，成功后就地翻水印再 `bump()`）。
- **封面**（`ui/cover.ts` + `components/Cover.tsx`，能力来自 `ui/termProbe.ts` + `ui/caps.ts`）：按终端能力自动选路（`QISHUI_TUI_COVER=kitty|ansi|off` 可强制，强制时连探测都不发）——**支持不支持靠开机那一次探测**（`a=q` 查询 + XTVERSION + DA1 收尾），不靠 `KITTY_WINDOW_ID`/`TERM` 猜：探到会答 kitty 图形协议、且牌子不在旧协议名单（`konsole`/`warp`——它们答查询但没有 unicode 占位符）就用 `chafa` 把任意格式解成原始 RGBA、走 kitty 图形协议贴**原图**（虚拟放置 `U=1`），正文只画 `U+10EEEE` 占位符（前景色 = 图片 id，图按 id **引用计数**、最后一处卸载才发 `a=d` 删除）；占位符是普通文字，ink 每帧整屏重画时图跟着占位符走、不会被擦掉（直接定位贴的 Sixel/iTerm2 图会被下一帧擦掉，那两条本轮不做）。探不到（mux 吃掉报文 / 不答的老终端 / 非 TTY）就用 `chafa` 的彩色半块 `▄`，解析成每格 fg/bg 再用 `<Text color backgroundColor>` 画。两条路都**只依赖本机 `chafa`**。**没封面就不占位置**：`coverUrl` 为空直接不画；有 url 但拉不到图（无 chafa / 断网 / 解析失败）由 `Cover` 回调 `onEmpty`，这一块整块收掉、行数还给歌词——不留等高空白。**字节优先本地**：core 已把封面落在 `~/.qishui/cache/tracks/<id>/cover.jpg`，页面传 `cacheKey` + `load`（`core.media.cachedCover(id)`）就不再打 CDN，本地没有才回源；内存 LRU 32 张，尺寸变了才重解。
- **封面占多大**：`2N × N` 格（像素上近似正方，与终端 1:2 的格宽高一致），`N = clamp(3, 12, 剩余高度/2)`，宽不超过左栏。kitty 路的 chafa 尺寸跟着这块格子走（`--size ${cols}x${rows}` + `--stretch`）：既保证方形封面不变形，也把传图载荷压在几百 KB 以内。
- **右栏 = 可收起的当前队列侧栏**：一行一首（在播那行 `>`、选中行下划线 + 序号），`↑↓` 挪游标、`Enter` 开这一行的操作菜单、点一行直接播；栏头两个可点按钮——`[切换队列]` 开弹层（每份队列一行，`(x)` 标当前那份，点谁切谁；末尾一条进「播放队列」页管理）、`[收起]` 把整栏换成一条摘要带（`播放队列 N 首 · 标题 · 第 k 首` + `[展开]`，`q` 同效）。播放条上的队列计数也是进「播放队列」页的可点入口。窄屏退成 `[歌词] [队列]` 两个 tab，队列不会被藏掉（`[收起]` 不画——tab 本来就能切走）。
- **队列窗口固定 `QUEUE_WINDOW = 10` 行**（可用高度不够 10 行才退让）：推荐队列只往后追加、能长到几百首，可视区不能跟着长。窗口只是「看到哪一段」——游标一出这 10 行就带着它滚（`windowFor`），所以 `↑` 能一路回看听过的、把它们再点一遍；行号是那首在队列里的**真实序号**，追加与跳播都不会让它挪位。`↓` 停在最后一行再按一次 = **主动要下一批**（core 的 `queues.loadMore()`，不等「剩 ≤2 首」那个阈值；补回来的游标落到新增那批的第一首）。
- **点一行 = 播这一行的那首，两件事各自成立**：① **不吃键盘焦点**——鼠标落在哪一栏就在哪一栏起效，点完顺手把焦点交给内容（与列表页 `mouseActive` 同一口径）。曾经队列行的点击挂在 `active`（= 焦点在内容区且无弹层）上，而启动时焦点默认在侧边栏，于是「刚进来点队列毫无反应」。② **按曲目 id 播，不按行号**——行号是界面那一刻的快照，中途有人被「从队列移除」就会让后面那些集体前移，拿老行号跳要么播成隔壁那首、要么越界被静默拒掉（点了没反应）；core 的 `player.playQueueTrack(id)` 收 id，找不着才给一句「这一首已经不在队列里了」。
- **歌词**：`player.lyricState()` 当前行**逐字高亮**（已唱 = 青 / 当前词 = 黄 / 未唱 = 默认，只用颜色、不用背景块），试听片段按整曲时间轴对齐。
- **歌词是局部滚动窗口，不铺满剩余高度**：窗口固定 `LYRIC_WINDOW = 7` 行（奇数，地方不够再缩到 5/3/1），**正在唱的那句永远在正中**、上下各 3 句上下文；窗口整体在剩余高度里垂直居中（上下留白）。歌刚开头 / 到结尾时窗口起点允许为负 / 越界，对应位置画留白，位置不跟着歌头歌尾跳。`↑/↓`（`k/j`）手动翻词、`g` 回到跟随播放头，点一句跳到那句；没有歌词时也占满这几行、提示句落在正中，高度不缩、下面布局不跳。
- 键位：模式用 `←/→`（`h/l`）+ `Enter`；`b` = **把游标交给两排操作按钮**（`btn` state 存的是被选中那颗的 key，不是下标——两排是同一份 `controls` 的两段切片，按 key 才对得上）：此后 `←/→` 在 8 颗按钮间循环挪、`Enter` 按下游标那颗、再按 `b` 还回模式行；游标回模式行时 `Enter` 才是「应用模式」，治的就是「在听歌页按回车全是切模式」。没在播曲目时 `b` 只 toast（按钮那一块根本不画）；换曲把游标交还模式行（上一首的选中位对这首没意义）。歌词用 `↑/↓`（`k/j`）+ `g`；队列栏用 `↑/↓`（`k/j`，游标出窗口就带着窗口滚、到队尾再按 `↓` 要下一批）+ `Enter`（开这一行的菜单）+ `g`/`G`（跳队首/队尾）；`t` = 歌词 ↔ 队列换栏（窄屏 = 换 tab；右栏收起时 = 展开并切过去）；`q` = 收起 / 展开右栏队列侧栏（窄屏 = 切到队列栏）；`o` = 当前曲目操作菜单；`R` = 重取模式列表。播放键（`Space` `n/p` `s` `r` `<`/`>` `+/-`）走全局表，不占页内键。鼠标可点模式、点开关（含 `[喜欢]`）、点歌词跳句、点队列行播它、点 `[切换队列]` / `[收起]` / `[展开]`、点曲名开菜单、点艺人·专辑进专辑/艺人页，队列栏上滚轮挪游标（窗口跟着滚）。
- 两个「当前」分开显示：模式行左侧 `听歌模式：xxx` = 本机记住的 `config.feedMode`（唯一真相源）；上游 `feed_mode_bar` 回的那一条只是上游栏的显示，两者不一致就并存（不替上游下结论）。场景里上游没给文案的照实显示 `场景 <id>`，不编名字。
- 续播机制在 core 的**推荐队列**（`packages/qishui-core/src/player/queues.ts` 的 `QueueBook`）：剩余 ≤ 2 首时异步追加**一整批**（一批 6 首就收 6 首，不因为「窗口装不下」截断），**只挂队尾、一首不删**；换模式作废在途结果，连续 2 次失败就停掉自动补批并提示（没有手动「停止续播」的开关）——见 §4.9.1。
- 当前模式落 `config.feedMode`（文法 `preference:<mode>` | `scene:<scene_mode_id>`〔短数字〕，空串 = 没选过），下次启动仍是它。
- **这一页是启动页**：程序起来就落在这里，core 一就绪就按记住的模式（没记住过 = 推荐档）取第一批并**自动起播**，之后按上面的机制续批。没记住过时只用推荐档跑，**不写 `config.feedMode`**（没选过还是没选过，不替人做选择）。`QISHUI_TUI_AUTOPLAY=0` 关掉自动起播。
- 用户明确点了别的内容（`playTracks` 这个总入口）= 换到那一份队列（歌单/喜欢/临时），推荐队列只是被切到后台**停着**，不是被覆盖——切回来还能接着听（见 §4.9.1）。
- **这一页只显示当前这一份队列**：右栏跟着在播队列走；同一时刻只有一份在播，其余各记各的位置，要切/收统一去「播放队列」页（侧边栏第 4 项 / `Q`，或点右栏头的 `[切换队列]` 弹层 / 播放条上的队列计数）。

### 4.7 曲目详情 TrackDetail（压栈）

- 上：**封面**（`2N × N` 格，`N = clamp(4, 8, (行数 − 8)/3)`——半块路低于 4 行就糊成一片，所以有下限）+ 曲名 / 歌手 / 专辑 / 时长 / `VIP` / 试听区间。宽到放得下就**左封面右文字**两栏（文字那栏至少留 24 列，`contentWidth` 算），窄了就封面单独一行；封面拿不到（无 url / 无 chafa / 断网）由 `onEmpty` 把整块收掉，不留空白。同一份 `Cover`，源图仍是 core 落在 `cache/tracks/<id>/cover.jpg` 的那张（本地优先，不再打 CDN）。

### 4.9 播放队列 Queues（一级，侧边栏第 4 项；`Q` 也可压在当下页之上，`Esc` 退回）

**独立一页**（不是弹层——弹层的 `Modal` 有最小宽度，窄终端会溢出）。队列是**按来源分的**书架：
同一时刻只有一份在播，其余各记各的位置；这一页把「有哪些队列 / 切到哪份 / 收掉哪份」摆成整幅，
任何宽度都进得来，是队列的**兜底入口**（不依赖别的页在不在）。

```
播放队列                                    2/10 份 · Enter 切过去 · d 收起选中的
队列
  > 推荐（在播）        推荐 · 6 首 · 第 3 首 · 晴天
    华语经典            歌单 · 42 首 · 第 8 首 · 七里香
当前队列 · 推荐（6）
    1 晴天 — 周杰伦            ← 按播放顺序；在播那行 `>` + 绿色
  > 2 稻香 — 周杰伦
    3 七里香 — 周杰伦
```

- 两段一个游标（`ui/entries.tsx` 的 `useEntries`）：
  - **「队列」段**：每份一行（`种类 · 数量 · 第几首 · 当前曲目`，在播那份标「（在播）」、推荐队列另标「自动续批」）；
    `Enter` 切过去（在播那份不动），`d` 把选中的**非在播**队列从书架收起（过确认框；在播的删不得，先切走）。
  - **「当前队列」段**：按**播放顺序**列当前这份队列的曲目（随机播放时与加入顺序不同），
    `Enter` 开这一行的操作菜单（与列表页同一份 `buildQueueTrackActions`），`d` 直接把这一行从队列移除。
- **上限 `MAX_QUEUES = 10`** 由 core 的 `QueueBook` 自动维护：每张歌单、每档听歌模式各占一份，听久了会攒出几十份；
  超了就在开新队列时**收起最久没用过的那份**（在播的那份永不淘汰），并给一句 toast（`queue-note`），
  页面标题里显示 `N/10`。收起的只是书架上的记录，不影响正在播的那一份。
- 书架 / 切队列 / 收队列的实现在 §4.9.1；`ui/queues.ts` 的 `queueKindLabel` 提供「种类」中文词。
- **出声不是 TUI 的事**：音频交给外部播放器（沿用 CLI 的 mpv 口径），TUI 只画状态。

#### 4.9.1 播放队列书架（侧边栏第 4 项 / `Q`）：一份队列一个来源

播放器**不是只有一个队列**：同一时刻只有一份在播，但「推荐 / 我喜欢 / 每张歌单 / 临时」各自是一份、
各自记着播到第几首 —— 听推荐听到一半去点一张歌单，推荐那条流不会没。实现在 core 的
`player/queues.ts`（`QueueBook`），界面只负责「打开 / 切换 / 显示」：

| 队列 | 谁产生 | 曲目 | 策略 |
|---|---|---|---|
| `recommend` 推荐 | 听歌模式（场景 / 推荐 / 熟悉 / 新鲜） | 上游每次一小批（实测 6 首） | **只往后追加**：听过的不删、跳播也不动已经排好的那些（每首的序号从头到尾不变，界面按固定 10 行的窗口滚着看）；后面剩 ≤2 首补**一整批**（给几首收几首，不截断），队尾还能源源不断地主动要；**顺序播、不随机** |
| `playlist` 歌单 | 每张歌单一份（本地歌单也算） | 整张 | 顺序播；切走再切回来接着上次那一首 |
| `liked` 我喜欢 | 「我喜欢的音乐」/ 本地喜欢 | 全部 | **随机** |
| `temporary` 临时 | 搜索 / 榜单 / 专辑 / 艺人 / 首页推荐块 | 这一次点播的那一批 | 顺序播；**每次点播整队替换上一批**（临时不留旧账） |

- **界面到队列的翻译**在 `ui/queues.ts`（`queueSpecOfSource`）：列表页的「播放这首」不是「覆盖播放器队列」，
  而是「把这首所在的那份队列切到前台」；歌单行 / 专辑行的「播放整张」自己带队列（不落到当前页那份）。
- `Q` / 侧边栏第 4 项打开**播放队列页**（§4.9）：每份一行 `标题 · 种类 · 数量 · 第几首`，`Enter` 切过去；在播那份标「（在播）」，
  推荐队列另标「自动续批」；`d` 收起选中的非在播队列（core 侧上限 10 份，超了自动淘汰最久没用的那份）。
- **书架持久化（重启还看得见）**：`QueueBook` 每次变化后 300ms 防抖把书架原子写进 `<dataDir>/queues.json`（先写 tmp 再 rename），
  `core.dispose()` 退出前 `flush()` 收尾；启动时 `hydrate()` 恢复每份队列的曲目、播到第几首、随机/续批状态——推荐队列连档位
  （`feed` 是可序列化的 `FeedModeRef`）一起回来，「启动即起播」因此是**接着上次那一首**而不是重新来一批。恢复时不认
  「上次在播哪份」（播放器重启后是空的），也不在恢复期取网（`loaded` 照抄落盘值）。两个边界：① `load` 闭包没法序列化——
  歌单/喜欢没取完的那部分曲目要回列表页再点一次才补齐；② `TrackData.raw` 原始响应快照不写盘（占地方且界面用不到），
  换号 `reset()` 整份作废并落盘。
- 续批失败连两次就停掉自动续批（留一句 toast），队列里已有的照样播完 —— 与老的 `FeedStream` 同口径，
  但状态机搬进了 core（界面不再自己记「流在不在跑」）。
- **循环模式**：新队列默认取设置页的「默认循环模式」，**推荐队列固定「关」**——它是自动续批的流，
  单曲循环会让播放头停在原地、续批永远不触发（一首歌无限重播）。在推荐队列上手动按 `r` 到「单曲」仍允许，
  但会 toast 提醒一句；切走再切回来会降回「关」。
- 换号（`useAccount`）时书架整份清空：我的喜欢 / 我的歌单换了号就是另一套。

### 4.11 本地 Local（一级，侧边栏第 6 项）

**「这台机器自己的音乐」一页收齐**，与「我的」那份云端收藏/歌单**并列但不合并**（两个真相源：云端要登录要联网、本地不出网匿名可用）。数据在 `~/.qishui/local/library.json`（`core.local`）+ 播放历史 `journal/*.jsonl`。

| 区块 | 内容 | 操作 |
|---|---|---|
| 本地喜欢 | `local.likes()`：条目可以是磁盘文件，也可以是云端曲目的快照（离线时照样看得见自己收过什么） | `Enter` → 列表页；加/取消在曲目菜单的「本地喜欢（切换）」 |
| 播放历史 | `local.history()`：`journal` 的曲目视图（新的在前），纯本地拼装、不发一个请求 | `Enter` → 列表页；「清空本地历史…」过确认框（云端「最近播放」不动） |
| 本地歌单 | `local.playlists()`（`N` 新建） | 每行 `Enter`：打开 / 播放整张 / 改名 / 删歌单（磁盘文件不动） |
| 音乐文件夹 | `local.folders()`（`A` 添加，`~/Music` 写法也认；目录不在了就写「找不到这个目录」） | 每行 `Enter`：打开（扫这个目录）/ 播放这个文件夹 / 重新扫描 / 移出列表；另有「全部扫描一遍」只报数量 |
| 操作 | 刷新 `R`、本地库文件路径（只读） | |

- **扫描只认文件名**：不引第三方 tag 解析库（core 零运行时依赖），`01 - 艺人 - 歌名.flac` 猜艺人/曲名、专辑名用目录名；**时长等播放器报回来再回填**（`local.rememberDuration`）。上限 5000 个文件 / 12 层目录，到上限如实标「只扫了一部分」。
- **播放**：磁盘文件的 `TrackData.localPath` 就是播放源（`PlaySource.kind = 'local'`），core 不下载也不缓存，直接把路径交给 mpv；播放条来源标 `文件`。文件被删了就是「本地文件不在了」，不去撞上游分享页。
- **本地曲目的菜单只有本地动作**（播放/下一首/队尾/本地喜欢/加入本地歌单/文件路径）：评论、详情、加入歌单、相似歌曲、不感兴趣、举报都是上游的动作，磁盘文件没有这些；反过来本地动作**不需要登录**，所以也不会出现「（需登录）」与「去登录」。
- 列表里的「已喜欢」一列对本地来源同样成立：本地喜欢是 `core.local` 自己知道的（`localTrackRows` 顺手把水印盖上），不用问上游。

## 6. 状态与错误口径

- 每个页面三态：`loading`（骨架）、`empty`（一句话 + 下一步建议）、`error`（区分 `CoreError` / `NotLoggedInError` / 上游错误，行内展示，可重试）。
- 列表**异步逐块渲染**：先出头信息再出条目。
- `NotLoggedInError` / `AuthRequiredError`：页内提示「需要登录」+ 一键开账号页，不回退成空白。
- `MediaUnavailableError`：标「本条不可播 / 未验证」，播放时跳下一首（`skipOnError`）。
- 无 TTY：与非交互对齐，跑一帧后正常退出（沿用现有降级逻辑）。

## 8. 与 core / CLI 的对应

- 页面不直接碰 `qishui-api`，只走 `qishui.<service>.<method>`（必要时 `qishui.request('端点', params)`）。
- 同一份数据在 CLI 与 TUI 是**同一个 core 调用的两种渲染**：CLI 三线表 / TUI 列表页共享字段口径（含「id 默认显示」约定）。
- 侧边栏的「听歌」独立项，与 CLI 的 `modes`+`radio` 命令一一对应，方便对照实现；榜单不再独立成项——CLI `charts` 列的那批榜单块，在 TUI 就是「发现」页里的分区条目。**口径不同**：CLI 的 `play radio:<id>` 是「取一批来播」（实测一次约 6 首），TUI 的「听歌」页也是取一批 + 自动续一批；两边都不把它当可浏览列表。
