# qishui-tui 页面设计（侧边栏导航）

> 配套输入：[`DATA_TYPES.md`](./DATA_TYPES.md) —— 现有 API/core 能拿到的**可用数据类型清单**（逐字段 + 来源 + 匿名/登录口径）。

目标：在**已有 `qishui-core` 能力**（不新增上游调用）之上，给终端一个**操作清晰、结构简单**的界面。
导航用**左侧边栏**常驻，一级功能一眼可见、随时可切；详情/播放靠压栈与覆盖层，不挤占侧边栏。

---

## 1. 设计原则

1. **能复用就不新增页面**：core 里绝大多数内容都是「一个曲目列表 + 一段头信息」（榜单/歌单/专辑/艺人/搜索/最近播放/块下钻…），所以只做**一个通用列表页**，用参数区分来源。唯一的例外是「听歌」——上游听歌模式一次只随机回一小批，不是一屏可浏览的列表，所以它是一页「模式单选台」而不是列表（见 §4.4）。
2. **侧边栏只放一级功能**：搜索、发现、听歌、我的、本地、设置。榜单不另起一项——首页榜单块在「发现」里已经摊平；登录/切号也不另起一项——并进了「我的」。详情、播放、登录都是压栈或覆盖，不增加侧边栏项。
3. **状态常驻可见**：侧边栏常驻 + 底部播放条常驻，任何时候都知道「我在哪、在播什么」。
4. **一份数据两条出路对齐 CLI**：列表沿用 CLI 三线表口径，同一个 core 方法喂两个前端。
5. **不替上游下结论**：拿不到地址 / 无权限，就地标「不可播」「未登录」，不静默吞。
6. **只用 ASCII + 汉字**：状态、模式、音量一律中文词（`播放` `循环:关` `音量:60`），选中/当前行用 `>`，错误用 `x`——不掺表情符号和装饰图形（`▶⏸🔊♥★▍` 那类）。理由不是审美：同一个码位在 emoji 呈现 / 中文字体下常占 2 格，`displayWidth()` 估不准，播放条与列表列会跟着错位。词表集中在 `ui/theme.ts`，模式标签集中在 `ui/playMode.ts`；唯一的例外是进度条 `━●─`（它本身就是终端图形，且每格只画它一个字符）。

## 2. 整体框架

```
┌──────────────┬────────────────────────────────────────────┐
│  搜索     /  │  听歌 · 选一个模式 · 随机取一批   Yinx VIP   │  ← 顶栏：面包屑 + 账号
│  发现        ├────────────────────────────────────────────┤
│ |[听歌]      │                                            │
│  我的        │        内容区（列表 / 详情 / 表格）          │
│  本地        │                                            │
│  设置        │                                            │
│              │                                            │
│              │                                            │
│  ──────────  │                                            │
│   未登录     │                                            │  ← 侧边栏底部：登录态
├──────────────┴────────────────────────────────────────────┤
│ 播放 红色高跟鞋 — 蔡健雅  ━━━━●────── 1:02/3:27 音量:60    │  ← 播放条（跨全宽）
│ Enter 播放   a 队尾   A 下一首   l 红心   c 评论   ? 帮助   │  ← 提示行（跨全宽）
└───────────────────────────────────────────────────────────┘
```

> 侧边栏两种标记（都不占背景色）：`|` = **当前所在的页**（焦点挪到内容区后只剩它，照样告诉你在哪一页）；
> `[方括号]`（accent 色）= **光标所在项**。启动时两者都在「听歌」上（`|[听歌]`）。

| 区域 | 内容 | 说明 |
|---|---|---|
| 侧边栏 | 6 个一级项 + 底部账号 | 固定宽度 16 列；最左一列是竖线 `|`（当前页），光标项用带颜色的 `[方括号]` 包起来——**不用反色色块**（整行反色在浅色/透明背景的终端上会糊成一条）；当前页一直保持 accent 色，进详情时也亮着 |
| 顶栏 | 面包屑 + 账号/会员标 | 压栈时显示 `‹ 发现 / 歌单`；宽度紧张时面包屑截断 |
| 内容区 | 当前页 | 见 §4；**选中的行 = `>` 前缀 + 下划线 + accent 色**（不用反色块，行内的在播绿/错误红不会被盖掉） |
| 播放条 | 状态 + 曲名/歌手 + 进度 + 模式 + 音量 + 来源 | 控件一律中文词（`播放` `音量:60` `循环:关` `随机:关`）；一行装不下就按优先级从尾巴往后丢（时间/音量保底），被丢的模式开关在播放页里常驻可见。`f`（或点曲名/队列计数）压栈进**播放页** |
| 提示行 | 只显示**当前页可用**的键 | `?` 看完整帮助 |

### 侧边栏项 → 页面

| # | 项 | 快捷键 | 根页 | 数据来源 |
|---|---|---|---|---|
| 1 | 搜索 | `1` `/` | 搜索页 | `search.*` `suggest` `categories` |
| 2 | 发现 | `2` | 发现页（首页大盘的**内容浏览**：榜单/歌单/专辑/艺人/曲目 + 歌单广场入口） | `discover.home` `discover.playlistSquare` |
| 3 | 听歌 | `3` | 听歌模式单选台：常用三档 + 场景，选中即起播（场景电台只在这页处理，发现页不混） | `discover.feedModes` `feedModeTracks` |
| 4 | 我的 | `4` `0` | 账号 + 我的音乐（登录/切号/登出与收藏/歌单/最近在一页） | `login` `accounts` `useAccount` `membership` `library.*` `history.*` |
| 5 | 本地 | `5` | 本地库一页收齐：本地喜欢 / 本地历史 / 本地歌单 / 音乐文件夹（**不出网、匿名可用**；与「我的」那份云端收藏/歌单是两个真相源） | `local.*` `history.*` |
| 6 | 设置 | `6` / `S` | 设置与缓存（`S` 压在当下页之上，`Esc` 退回；侧栏项直接切页） | `cacheStats` `clearCache` `config` |

> 侧边栏底部那行是**状态**也是入口：未登录显示 `未登录`，登录后显示 `昵称`，点击/`Enter` 进「我的」（账号操作已并在那一页）。
>
> **启动页是「听歌」（第 3 项）**：它是唯一会自己出声的页——core 一就绪就按记住的 `config.feedMode`（没记住过就用推荐档）取第一批并自动起播，播完自动续批。想先看别的页按 `1`/`2`/`4` 就行；`QISHUI_TUI_AUTOPLAY=0` 可关掉自动起播（离线自检、或不想一开就被声音打断）。

### 导航模型

```
侧边栏（常驻，切换一级页）
   搜索 · 发现 · 听歌 · 我的 · 本地 · 设置
        │
        └─ push ─► 列表页 ─push─► 曲目详情
                    ├─ push ─► 播放页（左：曲目信息 + 歌词，右：播放队列）
                    └─ 覆盖层：帮助 / 登录 / 加歌单 / 评论 / 操作菜单 / 确认
```

- **压栈的详情/列表**：`Esc` 逐层退回，回到一级页根后再 `Esc` 把焦点移到侧边栏（不退出）。
- **焦点区只有 3 处**：侧边栏 / 内容（含搜索输入行）/ 弹层。`Tab`（`Shift+Tab` 反向）在三者间循环，焦点在侧边栏时 `↑↓` 选项、`Enter` 进入、`1..6` 直达。
- **每一级页独立保留自己的浏览位置**：切走再切回来，列表游标与滚动不丢。

### 窄终端适配

- 宽度 ≥ 72：正常两栏（侧边栏 16 列）。
- 宽度 < 72：侧边栏**收窄成图标/首字模式**（约 4 列，如 `搜` `发` `听` `我`），选中项仍高亮。
- 宽度 < 48：侧边栏**隐藏**，按 `Tab` 或 `,` 把焦点交给导航时以浮层形式临时唤出（覆盖在内容上，选完自动收起）。
- 播放条与提示行始终各固定一行、`truncate-end` 不换行（沿用现有 resize 方案 `useFullscreenRows()`）。

## 4. 各页面内容

### 4.1 搜索 Search（一级）

```
关键词 晴天                                        [清空]
← 综合 · 歌曲 · 专辑 · 歌手 · 歌单 · 视频 →        ← categories()
──────────────────────────────────────────────────────
歌曲
  1  晴天  周杰伦  4:29   7627888436947339298
  2  …
歌手   （「综合」按分组，每组前 3 条 +「查看全部 →」）
```

- 输入中：`suggest()` 联想下拉（防抖 250ms，最多 6 条）；`↑↓` 在高亮里走，`Enter` 或点一下把词回填输入框——**回填不重新联想**，面板原样留着，只有敲键盘才刷新。
- 提交：按当前分类调 `search.search/tracks/albums/artists/playlists`。
- 结果行：`Enter`（或点一下）开**这一行的操作菜单**（`buildRowActions`，与列表页同一条路）——曲目 播放这首/下一首播放/加入队尾/我的喜欢/评论/详情…，歌单与专辑 打开 + 播放整张 + 收藏，艺人 热门/全部歌曲/全部专辑/关注。**Enter 不再直接把第一首播出去**。
- `←/→` 切分类；每组末尾的「查看全部」进对应分类的列表页（20 行/页，滚到底接着拉 —— 上游按类型搜有 `next_cursor`，`all` 的预览组没有）。

### 4.2 发现 Discover（一级）

纵向滚动的「卡片分区」，`Enter` 下钻：

| 分区 | 内容 | 进入后 |
|---|---|---|
| 榜单 | 首页榜单块（名称 + 曲目数） | 列表页 `chart:<id>` |
| 歌单 / 专辑 / 艺人 / 曲目 | 各首页块摊平的行 | 列表页 `playlist:<id>` / `album:<id>` / 详情 / 直接播 |
| 歌单广场 | 入口 | 列表页 `square[:categoryId]` |

- 一次 `discover.home({layout:'grid'})`；首启引导看 `launch().boost.needSet`（有则提示，不强制弹）。
- **听歌模式与场景不在这页**：早期这里有一条「随便听听」和一批 `radio:<id>` 场景条目，跳的都是「电台」列表页——那批接口一次只随机回一小批，不是可浏览列表。现在这一职责整个收在「听歌」页（§4.4），发现页只做内容浏览，不留第二个入口。

### 4.3 榜单（不独立成页，就在「发现」里）

- 首页 `discover_top_song_list` / `discover_track_top_list` 块的每个条目本身就是一个榜单入口（名称 + 曲目数），「发现」页已经把它们摊平成分区条目。
- `Enter` → 列表页 `chart:<id>`（带名次/涨跌箭头：`1 ↑2`、`5 ↓1`、`8 –`）；整榜用 `catalog.chart()`。
- 早期另有一个「榜单」一级页，把同一批块再摊一遍——两个入口一份数据，已删掉那一项。

### 4.4 听歌 Listen（一级）

一页**模式单选台**：只能有一个当前模式，选中即按它取一批起播，一批播完自动续下一批。

```
听歌   选一个模式 · 随机取一批 · 播完自动续 · 当前：熟悉
──────────────────────────────────────────────────────
常用
  (x) 推荐                                        ← preferences
  ( ) 熟悉                  （上游当前）
  ( ) 新鲜
场景
  更多场景（45）>  选择        选一个即按它起播     ← scenes → 弹层
自动续播
  停止自动续播            剩 2 首就补一批 · 当前 熟悉
```

- 数据来源就一个：`discover.feedModes()`（`preferences` + `scenes`）。取值动作走 `discover.feedModeTracks(ref)`——**两档都打 `FeedSongTab`**：偏好档落 `preference_mode`，场景档落扁平 `feed_preference.scene_mode_id`（早先场景错走 `FeedRadioTracks`，那条路的 `radio_id` 只认电台队列，短数字被忽略、回的是通用池，所以「选日语推中文歌」）。都是一次约 6 首的批次，所以这里不画列表、不分页、没有「加载更多」。
- 两个「当前」分开显示：`(x)` = 本机记住的 `config.feedMode`（唯一真相源）；`（上游当前）` = 上游 `feed_mode_bar` 回的那一条，只是上游栏的显示，两者不一致就并存。
- 场景有 45 条，收进 `ActionMenuOverlay` 弹层（自带按游标滚动），页面上只留一个「更多场景（N）> 选择」闸门；上游没给文案的场景照实显示 `场景 <id>`，不编名字。
- 「停止自动续播」是页内一条条目，不占散键；流不在跑时那一条换成「按「X」再来一批」（整队换一批），没选过模式则是一条说明。
- 续播机制在 core 的**推荐队列**（`packages/qishui-core/src/player/queues.ts` 的 `QueueBook`）：剩余 ≤ 2 首时异步追加一批（一批 6 首、窗口钳在 2~8 首），换模式/停流作废在途结果，连续 2 次失败就停掉自动续播并提示——见 §4.9.1。
- 当前模式落 `config.feedMode`（文法 `preference:<mode>` | `scene:<scene_mode_id>`〔短数字〕，空串 = 没选过），下次启动仍是它。
- **这一页是启动页**：程序起来就落在这里，core 一就绪就按记住的模式（没记住过 = 推荐档）取第一批并**自动起播**，之后按上面的机制续批。没记住过时只用推荐档跑，**不写 `config.feedMode`**（没选过还是没选过，不替人做选择）。`QISHUI_TUI_AUTOPLAY=0` 关掉自动起播。
- 用户明确点了别的内容（`playTracks` 这个总入口）= 换到那一份队列（歌单/喜欢/临时），推荐队列只是被切到后台**停着**，不是被覆盖——切回来还能接着听（见 §4.9.1）。

### 4.5 我的 Library（一级）

| 区块 | 内容 | 操作 |
|---|---|---|
| 账号头 | 昵称 / 头像位 / `VIP` / 数据目录 | `L` 进账号页（未登录时） |
| 快捷入口 | 我喜欢的音乐、最近播放、关注的艺人、收藏的歌单专辑混排 | `Enter` → 列表页 |
| 我的歌单 | `library.playlists()`（含 `type=1` 我喜欢的音乐、`type=4` 抖音收藏） | `Enter` 进歌单；`n` 新建；`r` 改名；`d` 删除（确认） |

- 最近播放以**本地历史** `history.recent()` 为准（上游 `GetRecentPlayedMedia` 写回不落地）。
- 未登录：显示可匿名部分 + 「登录后同步」提示，不隐藏整页。

### 4.6 列表 ListScreen（通用页，最重要）

一份骨架，参数化来源：头信息 + 曲目表 + 可选分页。

```
歌单 · 华语经典        42 首 · 更新 2026-10              ← 头
──────────────────────────────────────────────────────
  1 > 晴天          周杰伦      4:29       762…        ← > 当前播放行
  2    红色高跟鞋    蔡健雅      3:27       706…
  …
↓ 加载更多 (L)                                           ← 有游标时
```

| 来源参数 | core 调用 | 头信息 |
|---|---|---|
| `liked` | `library.likedPlaylist()` / `likedTracks()` | 我喜欢的音乐 |
| `playlist:<id>` | `catalog.playlist` + `playlistTracks` | 标题/简介/曲目数 |
| `album:<id>` | `catalog.album` / `albumTracks` | 专辑名/发行日 |
| `artist:<id>:hot\|tracks\|albums` | `artistHotTracks` / `artistTracks` / `artistAlbums` | 艺人名 + tab |
| `chart:<id>` | `catalog.chart` | 榜单名 + 名次/涨跌 |
| `mix:<blockType>:<innerId>` | `discover.mix` | 块标题 |
| `square[:cat]` | `discover.playlistSquare` | 歌单列表（条目→歌单列表页） |
| `search:<type>:<q>` | `search.*` | 结果头 |
| `recent` | `history.recent()` | 本地播放历史 |
| `user-playlists:<uid>` / `mixed-collections` | `social.userPlaylists` / `library.mixedCollections` | 他人 / 我的收藏 |

> **听歌模式不在这张表里**：偏好/场景两个来源（旧的 `feed:<mode>`、`radio:<id>`）已从 `ListSource` 删掉——上游那两条接口一次只随机回约 6 首，拿它们凑一屏「可浏览列表」是假象（每进一次都是另一批）。它们改成「听歌」页的批次来源，见 §4.4。

**统一操作**：`Enter` 播放选中、`a` 进队尾、`A` 下一首播、`l` 红心、`c` 评论、`i` 详情、`o` 跳到所属专辑/艺人、`L` 加载更多、`g/G` 顶/底、鼠标滚轮滚动、点击选中。

### 4.7 曲目详情 TrackDetail（压栈）

- 上：曲名 / 歌手 / 专辑 / 时长 / `VIP` / 试听区间 / 封面位。
- 中：统计（收藏 / 评论 / 分享）、来源状态（`cache` 本地已落盘 / `remote` 签名地址 / **拿不到 = 标「本条不可播」**）。
- 下：入口列表 —— 相似歌曲 → 列表页、评论 → 弹层、歌词 → 播放页、专辑/艺人 → 详情或列表页。

### 4.8 账号 Account（一级，`0`）

### 4.9 播放页 Player（压栈，任意页 `f` 打开；再按 `f` 或 `Esc` 退回）

**独立页面、左右两栏**（早期是覆盖层，`t` 在歌词/队列之间二选一 —— 一开操作菜单就把歌词盖掉，所以改成页面）：

```
正在播放  播放  ·  队列 12 首  ·  焦点：歌词            ← 页头
──────────────────────────────────────────┬───────────────────────
 晴天（很长很长的歌名…）                  │ 播放队列          3/12
 周杰伦  ·  叶惠美                        │ >  3 晴天 — 周杰伦
 ●──────────────────── 1:02/4:29          │    4 红色高跟鞋 — 蔡健雅
 [上一首] [播放] [下一首]                  │    5 演员 — 薛之谦
 [操作] [循环:关] [随机:关] [音量:60]      │    …
 歌词                          跟随播放头 │
                                          │   ← 留白：歌词窗口在剩余高度里居中
   上一句                                │
 > 当前行（逐字高亮）                     │   ← 正中那行永远是当前句
   下一句                                │
                                          │   ← 留白
```

窄屏（内容区 < 64 列）不再把队列藏掉，而是**单栏 + 顶部 tab**（`t` 或点 tab 换；方括号 = 当前栏）：

```
正在播放  播放  ·  队列 12 首  ·  焦点：队列
  歌词   [队列]                        12 首
 播放队列                            [队列]
 >  3 晴天 — 周杰伦
```

| 栏 | 内容 | 操作 |
|---|---|---|
| 左（曲目信息 + 歌词控制） | 曲名 / 艺人·专辑 / 进度条 / `[上一首] [播放] [下一首]` / `[操作] [循环:] [随机:] [音量:]` / 歌词 | 点曲名或 `[操作]` = 当前曲目的操作菜单；点艺人·专辑进专辑或艺人热榜；点/滚进度条定位；点一句歌词跳到那句；`↑↓` 手动翻词、`g` 回到跟随播放头 |
| 右（播放队列） | `player.queue.playOrder`，当前行 `>` + 绿色、选中行 `>` + 下划线 + accent | `↑↓`/`gG` 挪游标、点一行播它、`Enter` = 这一行的操作菜单 |

- **两侧的菜单是同一份**：`ui/rowActions.ts` 的 `buildTrackActions`（详情 / 喜欢 / 评论 / 加入歌单 / 相似歌曲 / 不感兴趣 / 举报）——列表页的行、播放页的当前曲目、队列里的行都用它；队列行由 `buildQueueTrackActions` 在两头各加一项：「立即播放这首」（跳到那一行，不是把整队换掉）与「从队列移除」（`player.removeFromQueue`，移掉的正好在播就接着播新的当前）。
- 歌词：`player.lyricState()` 当前行**逐字高亮**（已唱 = 青 / 当前词 = 黄 / 未唱 = 默认，只用颜色、不用背景块），试听片段按整曲时间轴对齐。
- **歌词是局部滚动窗口，不铺满剩余高度**：窗口固定 `LYRIC_WINDOW = 7` 行（奇数），**正在唱的那句永远在正中**、上下各 3 句上下文；窗口整体在剩余高度里垂直居中（上下留白）。歌刚开头 / 到结尾时窗口起点允许为负 / 越界，对应位置画留白，位置不跟着歌头歌尾跳（早期是「剩余几行就铺几行」，一句一行铺满一屏，视线要扫一大片）。没有歌词时也占满这 7 行、提示句落在正中，高度不缩、下面布局不跳。
- 焦点只有左右两栏，`t` 切换（点哪边就归哪边）；`Space` `n/p` `s` `r` `<`/`>` `+/-` 走全局表，不占页内键。
- 窄终端（内容区 < 64 列）退成单栏 + 顶部 tab：`[歌词] [队列]`（方括号 = 当前栏），`t` 或点 tab 切换——队列**不再被藏掉**，而是明确摆出「还有一栏」。键位不变。
- **出声不是 TUI 的事**：音频交给外部播放器（沿用 CLI 的 mpv 口径），TUI 只画状态。

#### 4.9.1 播放队列书架（`Q` / 右栏 `[队列]`）：一份队列一个来源

播放器**不是只有一个队列**：同一时刻只有一份在播，但「推荐 / 我喜欢 / 每张歌单 / 临时」各自是一份、
各自记着播到第几首 —— 听推荐听到一半去点一张歌单，推荐那条流不会没。实现在 core 的
`player/queues.ts`（`QueueBook`），界面只负责「打开 / 切换 / 显示」：

| 队列 | 谁产生 | 曲目 | 策略 |
|---|---|---|---|
| `recommend` 推荐 | 听歌模式（场景 / 推荐 / 熟悉 / 新鲜） | 上游每次一小批（实测 6 首） | **滑动窗口**：每前进一首就把「上上个」踢掉；后面剩 ≤2 首补一批，窗口钳在 2~8 首；**顺序播、不随机** |
| `playlist` 歌单 | 每张歌单一份（本地歌单也算） | 整张 | 顺序播；切走再切回来接着上次那一首 |
| `liked` 我喜欢 | 「我喜欢的音乐」/ 本地喜欢 | 全部 | **随机** |
| `temporary` 临时 | 搜索 / 榜单 / 专辑 / 艺人 / 首页推荐块 | 这一次点播的那一批 | 顺序播；**每次点播整队替换上一批**（临时不留旧账） |

- **界面到队列的翻译**在 `ui/queues.ts`（`queueSpecOfSource`）：列表页的「播放这首」不是「覆盖播放器队列」，
  而是「把这首所在的那份队列切到前台」；歌单行 / 专辑行的「播放整张」自己带队列（不落到当前页那份）。
- `Q`（或播放页右栏的 `[队列]`）开书架弹层：`标题 · 种类 · 数量 · 第几首`，`Enter` 切过去；
  在播那份标「（在播）」，推荐队列另标「自动续批」。
- 续批失败连两次就停掉自动续批（留一句 toast），队列里已有的照样播完 —— 与老的 `FeedStream` 同口径，
  但状态机搬进了 core（界面不再自己记「流在不在跑」）。
- 换号（`useAccount`）时书架整份清空：我的喜欢 / 我的歌单换了号就是另一套。

用户 · 某某          VIP

  关注 12  粉丝 34  获赞 56  作品 7

- 入口：搜索结果的用户行菜单、评论弹层里 `Enter` 看作者、关注/粉丝列表里的人。

### 4.11 本地 Local（一级，侧边栏第 5 项）

**「这台机器自己的音乐」一页收齐**，与「我的」那份云端收藏/歌单**并列但不合并**（两个真相源：云端要登录要联网、本地不出网匿名可用）。数据在 `~/.qishui/local/library.json`（`core.local`）+ 播放历史 `journal/*.jsonl`。

| 区块 | 内容 | 操作 |
|---|---|---|
| 本地喜欢 | `local.likes()`：条目可以是磁盘文件，也可以是云端曲目的快照（离线时照样看得见自己收过什么） | `Enter` → 列表页；加/取消在曲目菜单的「本地喜欢（切换）」 |
| 播放历史 | `local.history()`：`journal` 的曲目视图（新的在前），纯本地拼装、不发一个请求 | `Enter` → 列表页；「清空本地历史…」过确认框（云端「最近播放」不动） |
| 本地歌单 | `local.playlists()`（`N` 新建） | 每行 `Enter`：打开 / 播放整张 / 改名 / 删歌单（磁盘文件不动） |
| 音乐文件夹 | `local.folders()`（`A` 添加，`~/Music` 写法也认；目录不在了就写「找不到这个目录」） | 每行 `Enter`：打开（扫这个目录）/ 播放这个文件夹 / 重新扫描 / 移出列表；另有「全部扫描一遍」只报数量 |
| 操作 | 刷新 `R`、本地库文件路径（只读） | |

- **扫描只认文件名**：不引第三方 tag 解析库（core 零运行时依赖），`01 - 艺人 - 歌名.flac` 猜艺人/曲名、专辑名用目录名；**时长等播放器报回来再回填**（`local.rememberDuration`）。上限 5000 个文件 / 12 层目录，到上限如实标「只扫了一部分」。
- **播放**：磁盘文件的 `TrackData.localPath` 就是播放源（`PlaySource.kind = 'local'`），core 不下载也不缓存，直接把路径交给 mpv；播放条来源标 `文件`。文件被删了就是「本地文件不在了」，不去撞上游分享页。
- **本地曲目的菜单只有本地动作**（播放/下一首/队尾/本地喜欢/加入本地歌单/文件路径）：评论、详情、加入歌单、相似歌曲、不感兴趣、举报都是上游的动作，磁盘文件没有这些；反过来本地动作**不需要登录**，所以也不会出现「（需登录）」与「去登录」。
- 列表里的「已喜欢」一列对本地来源同样成立：本地喜欢是 `core.local` 自己知道的（`localTrackRows` 顺手把水印盖上），不用问上游。

## 6. 状态与错误口径

- 每个页面三态：`loading`（骨架）、`empty`（一句话 + 下一步建议）、`error`（区分 `CoreError` / `NotLoggedInError` / 上游错误，行内展示，可重试）。
- 列表**异步逐块渲染**：先出头信息再出条目。
- `NotLoggedInError` / `AuthRequiredError`：页内提示「需要登录」+ 一键开账号页，不回退成空白。
- `MediaUnavailableError`：标「本条不可播 / 未验证」，播放时跳下一首（`skipOnError`）。
- 无 TTY：与非交互对齐，跑一帧后正常退出（沿用现有降级逻辑）。

## 8. 与 core / CLI 的对应

- 页面不直接碰 `qishui-api`，只走 `qishui.<service>.<method>`（必要时 `qishui.request('端点', params)`）。
- 同一份数据在 CLI 与 TUI 是**同一个 core 调用的两种渲染**：CLI 三线表 / TUI 列表页共享字段口径（含「id 默认显示」约定）。
- 侧边栏的「听歌」独立项，与 CLI 的 `modes`+`radio` 命令一一对应，方便对照实现；榜单不再独立成项——CLI `charts` 列的那批榜单块，在 TUI 就是「发现」页里的分区条目。**口径不同**：CLI 的 `play radio:<id>` 是「取一批来播」（实测一次约 6 首），TUI 的「听歌」页也是取一批 + 自动续一批；两边都不把它当可浏览列表。
